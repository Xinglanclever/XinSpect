═══ P2-026 是「既有實作的家族化」，而沒有改那個既有的鍵 ═══

SmbiosDeepFactsService 已經有 sb.psu（單一鍵，給人看的摘要），
而規格要的是 sb.psu.* 家族。**正確的處置是補上家族鍵，不是改掉舊的那把**
——鍵是已發佈的契約，改名會破壞既有使用者的匯出與查詢。

這一點寫進了 PsuCountKey 的措辭裡：
「這一項與既有的 sb.psu 是同一個結構的另一種切法」。

═══ 核心：功率的「未回報」與「0 瓦」之別 ═══

Type 39 的功率欄位用 0x8000 當「未回報」旗標：
  * 當數值讀 → 得到 32768 W，**一個荒謬但不會讓人懷疑的數字**
  * 當 0 讀  → 合計少算一台

三條測試釘住它：
  * 未回報的功率不得當成三萬兩千七百六十八瓦
  * 部分回報時合計只涵蓋回報的那些 →「未回報的不以 0 計入」
  * 全部回報時要說那是額定不是可用 →「轉換效率、各路輸出上限、
    以及同時啟動的峰值都不在這個數字裡」

還有一條守住「長度不足 ≠ 0 台」：
長度 0x0C 的 Type 39 沒有功率欄位，**那不是「0 台」，是「這一筆讀不出來」**。

═══ 界線 ═══

Type 39 是「電源供應器自己在說什麼」，不是量測。一個 PSU 宣告 1000 W
代表它的額定，不代表現在的輸出；「已插電」是旗標，不是瓦數。
本服務只陳述欄位內容，不換算、不推估、不判斷夠不夠用。

Type 41 的「參考指定」指向其他結構，本服務只計數不追進去
——那需要跨結構的關聯解析（列在另一項 sb.cross.*）。
