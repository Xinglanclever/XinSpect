ULTIMATE-1000 階段二 P2-052（FIT 表）退回未開工

═══ 徵狀 ═══

五條測試紅燈，全部同一個原因：解析器找不到表頭。
而**測試 helper 的佈局與解析器的搜尋方向衝突**——
helper 把表頭放在「尾端之前」，而解析器從尾端往回每 16 bytes 找一次。

═══ 而真正該停下來的地方 ═══

當我試著修正那個佈局時，我發現**我在猜 FIT 的佈局**：

  * 表頭簽章是 `_FIT_` 還是 `_FIT_` 加三個空白？
  * 項目數量欄位是 3 bytes 還是 4 bytes？
  * 項目大小欄位是「2 的冪次」還是「直接值」？
  * 版本欄位必須是 0x01 嗎？
  * 表頭在 BIOS 區的最後 16 bytes，還是更前面？

**而「表頭在最後 16 bytes」與「項目在表頭之後」兩個假設互相矛盾**——
如果表頭在最後 16 bytes，就沒有空間放項目。

**這個矛盾是線索：我的其中一個假設是錯的，而我不知道是哪一個。**

═══ 處置 ═══

**退回未開工。** 理由與 P2-008（HMAT）、P2-024（Type 19）、
P2-029 的 Type 44 那半完全相同：

**一個「測試會過但我不確定為什麼會過」的解碼器，
會對真實映像給出看起來合理的錯誤結果——那比沒有更糟。**

fit.present／fit.count 兩把鍵已從目錄移除，服務與測試已刪除。

═══ 修好的路徑 ═══

找到 Intel FIT 規格（或一份可信的開源實作，
例如 coreboot 的 `src/lib/fit.c`）可以逐欄位對照。
**在那之前不猜。**

═══ 而這是第四次同型撤回 ═══

  P2-008  HMAT        可變長度子結構
  P2-024  Type 19     欄位重疊（size 與型別）
  P2-029  Type 44     欄位重疊（參考控制代碼與型別）
  P2-052  FIT         佈局假設互相矛盾

**四次都不是「太難」，而是「我沒有依據」。**
而四次的共同徵狀都是「測試失敗 → 改偏移 → 再失敗」——
**那不是解碼，是擬合測試。**

═══ 而成功的那些有一個共同點 ═══

MADT／DMAR／SRAT／SMBIOS 各型別／UEFI 開機順序——**固定表頭 ＋
固定長度子結構，或欄位互不重疊**。這些我都一輪就過。
