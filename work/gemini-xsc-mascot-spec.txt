**一、設計題 1：強調色抉擇（唯一答案）**

**最終選擇：瑞士紅 `#E30613`（RGB `227, 6, 19`）**

1. **「曦＝破曉第一道光」與精密儀器的雙重語意**：日出並非一開始就是暖橘色；太陽躍出地平線前刺破深黑夜空的第一道高能折射光，正是極高純度的赤紅。同時，在硬體工程語境中，`#E30613` 是精密測量儀器（如 Leica 紅標、示波器觸發線、ThinkPad 指向點）與「唯讀封條（Security Seal）」的標準色，完美契合「硬體的事實，不編故事」的冷靜定位。
2. **與 Claude Code 的絕對品牌區隔**：`xsc` 已經借鑑了圓角框、`⏺`/`⎿` 結構與幽靈提示；若連強調色都採用 `#D97757`（Claude 標誌性的陶土橘），視覺上會淪為 Claude Code 的漢化分支。堅持使用 `#E30613`，能讓使用者在打開終端的第一秒就認出這是「曦覽 XinSpect」的家族產品（與你的瑞士國際主義網頁及桌面端視覺一脈相承）。
3. **深色終端的可讀性控制**：`#E30613` 彩度極高，若大面積鋪底（如紅底白字徽章）會在純黑背景產生眩光（Halation）。解法不是換成暗橘色，而是「收回紅色的面積，提高紅色的純度」——取消紅底反白塊，將 `#E30613` 嚴格收斂於細框線與單字元錨點（品牌符號、`⏺`、`>`），在深黑底色上會呈現如雷射雕刻般的銳利度。

**二、設計題 2：xsc 專屬符號設計（取代 `✻`）**

Claude 的 `✻`（U+273B）是 Anthropic 的專屬識別，xsc 必須擁有自己的圖騰。以下 3 個候選字元皆隸屬 CP437 傳統終端字元集或基礎幾何區塊，在 Windows Terminal（Cascadia Mono、Consolas、JetBrains Mono）中 **100% 原生支援、絕不變豆腐、且固定為 1 半形欄寬**：

* **候選 A：`☼`（U+263C，WHITE SUN WITH RAYS，空心光芒日輪）**
* **理由**：自 MS-DOS（CP437 第 15 號字元）時代就內建於所有 Windows 終端字型。字形直接就是「曦（晨光日輪）」，且中心為**空心圓**，象徵「唯讀、不改寫硬體、純粹透光觀測的鏡頭光圈」。


* **候選 B：`◈`（U+25C8，WHITE DIAMOND CONTAINING BLACK SMALL DIAMOND，雙層晶體菱形）**
* **理由**：象徵石英震盪器（Crystal Oscillator）、矽晶圓切割（Silicon Die）與探針準星，工程感極強，但少了「曦（日出）」的字面直覺。


* **候選 C：`◉`（U+25C9，FISHEYE，魚眼同心圓／探針觸點）**
* **理由**：像是主機板上的測試點（Test Point）與初升太陽的日核，結構極簡，但與完成符號 `⏺`（U+23FA）外型過於接近，容易在視覺掃描時混淆。



**【最終推薦】：選 `☼`（U+263C）作為 xsc 唯一品牌符號**

**`☼` 在各位置的精確配置規範：**

1. **歡迎框（Welcome Box）**：固定放於左上角首行第 1 個字元（`│ ☼ 曦覽終端機 xsc v3.16`），塗上瑞士紅 `#E30613`，直接取代原本的 `✻`。
2. **Spinner 動畫（破曉序列）**：放棄 Claude 的星芒旋轉 `✢✶✻✽`，改為專屬的「晨光破曉序列」——由微光點逐步擴張為日輪，再收回微光：
`∙` (U+2219) → `∘` (U+2218) → `○` (U+25CB) → `◎` (U+25CE) → `☼` (U+263C) → `◎` → `○` → `∘`
（寓意：從單一硬體訊號點 `∙` 逐層探測，最終照亮完整硬體事實 `☼`）。
3. **完成輸出符（`⏺`）**：**維持使用 `⏺`（U+23FA）**，不要換成 `☼`。因為一次輸出可能包含多個探針段落，若每段開頭都是 `☼` 會稀釋品牌符號的份量；`☼` 代表「xsc 系統本身」，`⏺` 代表「單一事實節點」。
4. **提示符（`>`）**：**維持使用單字元 `>**`（瑞士紅 `#E30613`），保持極簡輸入手感，不加 `☼` 前綴。
5. **GUI 圖標語意對應**：在 GUI（65 頁介面與網站）中，`☼` 對應「8 等分刻度光圈環繞空心圓」的幾何向量圖標——外環 8 道刻度代表 8 大硬體事實域（WMI / PCI / MSR / LHM / IPC / Redfish / Compliance / Merkle），中間空心圓代表「唯讀零干預（Zero-Mutation）」。

**三、設計題 3：xsc 現況檢視與具體修改建議**

根據【xsc 現況簡報】與真實指令集，現有設計有以下 **5 點具體改進建議**：

1. **拔除「紅底白字徽章」，改為「無底色紅字封印」**：
* **問題**：歡迎框外框已經是瑞士紅 `#E30613`，內部若再塞一個「紅底白字」的 `唯讀／不寫硬體／不連網` 徽章，在終端機裡看起來極像 `ERROR` 或 `FAIL` 警告標籤，且破壞了留白質感。
* **修改**：取消背景色（`\x1b[48;...`），改用純文字排在標題正下方：`唯讀`（紅粗體）`·`（Dim）`不寫硬體`（紅粗體）`·`（Dim）`不連網`（紅粗體），並在同行右側對齊口號 `硬體的事實，不編故事。`（Dim）。


2. **為歡迎框「減肥」：移出「旋轉小知識」與「`↑↓/Tab` 提示」**：
* **問題**：目前歡迎框塞了「標題＋徽章＋快速開始＋旋轉小知識＋`↑↓/Tab` 提示＋cwd」，資訊密度過高，失去了 Claude Code 歡迎框那種「一眼看穿」的呼吸感。
* **修改**：
* 將 `↑↓ 歷史 · Tab 補全` 往下移，固定放在 `>` 提示符正下方的 Dim 狀態列（那裡才是使用者打字時視線所在的位置）。
* 將「旋轉小知識」從歡迎框內拿掉，改為放在歡迎框外下方獨立一行 Dim 文字（例如：`💡 事實小知識：msr 讀取需 Ring0 通道就緒；未就緒時 xsc 必標示 [ -- ] 絕不捏造數值。`，把「💡」換成純文字 `註：`）。




3. **重組歡迎框「快速開始指令」，凸顯 1,178 靜態鍵、儀表板與證據鏈**：
* **問題**：只列 `facts / pages / help` 太過單薄，使用者不知道有 `fact <關鍵字>`、`dash`、`top`、`merkle`、`compliance` 這些核心武器。
* **修改**：將快速開始擴充為 **4 行結構化導覽**（主指令白粗體，延伸指令嵌入同行說明中），把真實指令集的核心脈絡一次交代清楚。


4. **將所有指令範例統一為「無斜線（No-Slash）」原生語法**：
* **問題**：xsc 真實指令是 `facts`、`pages`、`help`，而非 `/facts` 或 `/help`。
* **修改**：全面統一歡迎框、幽靈提示與說明文字，直接印出原生指令名稱（如 `facts`、`fact <關鍵字>`、`msr <索引>`）。


5. **區分「互動監控指令」與「單次事實查詢」的輸出過場**：
* **修改**：執行 `facts`、`pci scan`、`merkle`、`compliance` 時顯示 `∙∘○◎☼` Spinner 並收斂為 `⏺` 樹狀結果；執行 `sys` 時不跑 Spinner，直接秒印單行 `⏺` 快照；執行 `dash` 或 `top [秒]` 時切換至 Alternate Screen Buffer（`\x1b[?1049h`），按 `q` 離開後回到原本乾淨的 `⏺` 對話流，不留殘影。
