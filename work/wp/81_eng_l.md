## 第五十二章　完整案例：一份報告的判讀走查

### 52.1 案例的性質

本章以一個具體的案例說明報告的判讀方式。**案例中的數值為示範性質，其格式與欄位對應本專案的實際輸出，但數值為虛構**，以便呈現各種情形的判讀方式。案例的機器具備以下特徵：記憶體混批、一顆經過翻新的固態硬碟、一條降速的 PCIe 鏈路、以及一個因權限不足而未取得的項目。

### 52.2 脈絡資訊

```
工具版本     2.84
量測時間     2026-10-14 22:41:07
執行權限     系統管理員
虛擬層       未偵測到（R-CPU-04：相符）
作業系統     Windows（組建號已記錄）
```

**判讀。** 執行權限為系統管理員，因此需要 Ring-0 存取的事實應為可用。虛擬層未偵測到，因此後續的硬體層讀值為實體硬體的直接量測，不需依 49.6 的方式調整判讀。

若此處顯示「偵測到虛擬層」，則整份報告的硬體層事實需重新解讀，其診斷價值大幅下降。

### 52.3 部分事實與其判讀

**例一：一個讀不到的項目。**

```
名稱        逐核微碼版本
可用性      InsufficientPrivilege
原因        需以系統管理員權限執行，且需載入唯讀驅動
來源        MSR（Ring-0 讀取）
```

**判讀。** 此項目讀不到的原因是權限或驅動，而非硬體不存在。此情形下的正確反應是確認驅動是否已載入（見 50.1 的第一層）。**不應解讀為「此機器沒有微碼資訊」。**

**例二：一個記憶體事實。**

```
名稱        各條模組製造商
值          廠商甲 | 廠商甲 | 廠商乙 | 廠商乙
可信層級    Measured
來源        SMBus SPD
可用性      Present
```

**判讀。** 四條模組中有兩條來自廠商乙。此值本身只是陳述；其意義由對帳規則 `R-MEM-01` 判定。

**例三：一個推導事實。**

```
名稱        矽晶推算基礎頻率
值          3,600 MHz
可信層級    Derived
來源        由最大非睿頻倍頻×BCLK 推算
可用性      Present
```

**判讀。** 此值為推導，因此需要標示其推導方式。它與 CPUID 回報的宣稱基礎頻率的比較構成規則 `R-CPU-05`。

### 52.4 對帳結果與其判讀

**結果一：**

```
R-MEM-01   各條記憶體模組並非同批
判定       矛盾
說明       製造商或料號不一致，這幾條不是同一批出廠的模組。
證據       製造商：廠商甲 | 廠商甲 | 廠商乙 | 廠商乙
           料號：  A1B2 | A1B2 | C3D4 | C3D4
```

**判讀。** 兩條模組為同批，另兩條為另一批。此為**混批**的確認。混批的成因包括擴充記憶體、更換故障模組、或拼裝。**此判定不表示造假**，其意義取決於情境：若賣方聲稱機器為原廠配置，則此矛盾與該聲稱不符；若賣方已知並告知記憶體曾擴充，則此矛盾僅是確認陳述。

**結果二：**

```
R-SSD-02   已用壽命與累計寫入量對不上
判定       矛盾
說明       已用壽命為 0%，但累計寫入量已達 96,400 GiB，兩者的關係不合理。
證據       已用壽命：0 %
           累計寫入資料量：96,400 GiB
作用域     逐碟（磁碟 3）
```

**判讀。** 此為**計數器被重設**的強證據。其推論為：一顆已寫入 96,400 GiB 的裝置，其健康度不可能仍為 100%（已用壽命 0%）。此矛盾的成因包括控制器韌體重設計數器、以及工具的維護行為。**兩者皆為可陳述的事實**，而使用者應進一步查證（例如對照通電小時與通電次數，見 `R-SSD-01` 與 `R-SSD-03`）。

**結果三：**

```
R-LNK-01   PCIe 鏈路寬度低於裝置能力
判定       矛盾
說明       現行鏈路寬度低於裝置支援的最大寬度。
證據       現行寬度：x4   裝置最大寬度：x16
           現行速度：8.0 GT/s   裝置最大速度：16.0 GT/s
```

**判讀。** 鏈路降速與降寬同時發生。可能的成因包括插槽的實體佈線限制（x16 插槽實際只有 x4 的佈線）、電源管理設定、以及轉接卡的品質。**工具的陳述限於落差本身**；成因的判定需要主機板規格與實體配置的資訊。

**結果四：**

```
R-MEM-05   宣稱 ECC 與模組實際位元寬度對不上
判定       無法判定
缺少事實   記憶體陣列宣稱的錯誤更正型別
取得條件   需要 SMBIOS Type 16（此系統未提供該結構）
```

**判讀。** 此規則的輸入不齊備。**無法判定不等於相符**（見 49.3）：在此情形下，ECC 的存在與否未被確認。使用者若需要確認此事，需以其他方式查證（例如查閱模組的規格書或系統的技術文件）。

### 52.5 覆蓋說明

```
事實鍵總數        844
已覆蓋            （依規則計）
明文豁免          562
未覆蓋            （已知數字）
```

**判讀。** 使用者應注意未覆蓋的部分：這些事實未被任何規則交叉檢查，其可信度僅由其來源決定。若報告中的某個判斷依據落在未覆蓋的範圍內，該判斷的可信度需相應調整。

### 52.6 案例的綜合結論

由以上走查可歸納出四點。

**第一，矛盾清單的價值高於任何單一數值。** 案例中的三項矛盾（混批、計數器重設的跡象、鏈路降速）皆為可陳述、可複核、且與交易決策相關的資訊。

**第二，無法判定的項目必須被明確列出。** 案例中的 `R-MEM-05` 因缺少輸入而無法判定；若此項目被計入相符，報告將傳達錯誤的訊號。

**第三，判讀需要情境。** 混批與鏈路降速的意義取決於賣方的聲稱與交易條件；工具提供事實，情境來自使用者。

**第四，來源與可信層級必須被檢視。** 案例中的矽晶頻率為 `Derived`，其可靠性取決於推導方式；而所有硬體層事實為 `Measured`，其可靠性取決於量測環境（此案例中虛擬層未偵測到，因此量測環境可信）。

### 52.7 案例的限制

此案例為示範性質，其數值為虛構。實際的報告會包含數百筆事實與十餘條對帳結果，其判讀方式與本文所述一致，但細節更為豐富。此外，案例中未涵蓋的情形（例如偵測到虛擬層、多顆儲存裝置、伺服器模式的角色事實）在實際使用中亦會出現，其判讀方式見第六部各章。
