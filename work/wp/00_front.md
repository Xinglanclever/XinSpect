## 文件性質與範圍

本白皮書是曦覽（XinSpect）的完整技術說明文件，對象為三類讀者：需要評估此工具是否適用於其驗機或稽核流程的專業使用者；需要在既有架構上擴充事實來源或對帳規則的貢獻者；以及需要理解量測語意與其限制、以便正確引用輸出結果的審計人員。

本文並非行銷文件，也不重複 `README.md` 的操作教學。本文的目標是完整交代**設計意圖、資料模型、判定語意與工程約束**——亦即「為什麼是這樣做」與「這樣做的代價是什麼」。凡程式中可機械驗證的事實，本文一律以可重現的方式引用，並在附錄中列出全集。

本文的三個語言版本共用同一份機器產生的附錄資料。繁體中文版為原始撰寫版本；簡體中文版由 OpenCC 對繁體中文版進行台灣正體→大陸簡體轉換（字元層級並含用語轉換，如「專案」→「項目」、「介面」→「界面」）後產出，兩版逐段對應；英文版為另行撰寫之版本，敘述密度較為精簡，且附錄 B、D 以摘要方式呈現——該兩份附錄的理由文字於原始碼中以中文撰寫，全文見中文版，此差異在英文版的附錄導言中亦已載明。

## 摘要

曦覽是一款以 WPF（.NET 10）撰寫、執行於 Windows x64 的原生硬體驗機、監控與安全稽核工具，以單一可攜執行檔發佈，不需安裝。其核心設計主張可以一句話概括：**本工具不替使用者的硬體下結論，只把各個來源的陳述並列攤開，並具名標示其出處與可讀性。**

為落實此一主張，專案在所有層面採用了同一組約束：

- **事實模型統一**。所有觀測值收斂為單一型別 `HardwareFact`，具有鍵、分類、名稱、值、數值、單位、來源、可信層級、可用性與量測時間十個維度。時間膠囊、查詢語言、本機 API 與 HTML 報告全部消費同一模型，因此不存在「畫面上看到的」與「匯出的」不一致的情形。
- **三態誠實**。每一個事實都必須回答「這個值為什麼讀不到」。可用性欄位區分 `Present`（讀到）、`NotSupported`（平台無此能力）、`InsufficientPrivilege`（權限不足）、`ReadError`（讀取失敗）與 `NotApplicable`（不適用）。以 0 或典型值填補讀不到的欄位，在本專案被定義為缺陷而非取捨。
- **可稽核來源**。每個事實記錄其來源（暫存器位址、WMI 類別、API 名稱）。暫存器解碼器必須攜帶規格引用註記，並由反映式（reflection）機器檢查強制。
- **自驗量測**。牽涉效能的量測必須自證：西洋棋基準以 perft 作為數學檢核；頻寬換算在回報前先以已知大小的負載自驗；PMU 程式化每一輪都驗證寫入後回讀一致。
- **對帳而非評分**。跨來源交叉檢查輸出三種判定——相符、矛盾、無法判定——不輸出分數，也不輸出「正品」結論。矛盾具名列出來源雙方，判讀留給使用者。
- **豁免必須附理由**。不對帳的事實必須明文登記理由；覆蓋申報只申報不強制，因為強制全覆蓋會逼出湊數的規則，那比誠實申報一個數字更糟。

## 可重現性

本白皮書的附錄不是人工抄寫的表格，而是由版本控管中的產生器從原始碼抽取而成：

```
python work/wp_gen.py
```

產生器讀取 `Services/FactKeyCatalog.cs`（靜態鍵全集）、`Services/FactKeyDynamicCatalog.cs`（動態家族與理由）、`Services/VerifyRules.cs`（規則、分區、標題、所需事實與作用域）、`Services/FactCoverageReport.cs`（豁免前綴與理由），再掃描 `Services/`、`Tests/`、`docs/` 三個目錄，輸出附錄 A 至 G 的分割檔與 `stats.json`。

因此附錄與程式碼之間不會漂移：若有人新增事實鍵而忘了更新目錄，`FactKeyCatalogTests` 會失敗；若有人新增規則而使某個鍵不再未覆蓋，重跑產生器即可看到差異。這正是本專案一貫的做法——把「一致性」交給測試與產生器，而不是交給文件撰寫者的記性。
