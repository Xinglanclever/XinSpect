本詞彙表收錄本文件中具有特定語意的術語。定義以本專案的用法為準，與業界的一般用法可能略有差異。

### 核心模型

| 術語 | 定義 |
|---|---|
| 事實（Fact） | 一次觀測的結果，表示為 `HardwareFact` 的一筆實例。事實不是「真相」，而是「某個來源在某個時點對某件事的陳述」。 |
| 事實鍵（Fact key） | 事實的唯一識別碼，點分命名。鍵是程式的性質而非機器的性質：有哪些鍵取決於有哪些服務。 |
| 靜態鍵 | 編譯期固定於 `FactKeyCatalog` 的鍵，共 844 個。 |
| 動態家族 | 成員由機器決定的鍵家族，以字首登記於 `FactKeyDynamicCatalog`，共 23 個。 |
| 事實鍵目錄 | 靜態鍵的全集，位於 `FactKeyCatalog`，由測試與原始碼逐鍵比對。 |
| 前綴（Prefix） | 事實鍵的第一段，代表領域。本版有 107 個前綴。 |

### 可信度與可用性

| 術語 | 定義 |
|---|---|
| 可信層級（Trust level） | 事實的可信分類：`Measured`（本工具直接量測）、`Reported`（來源自述）、`Derived`（由其他事實推導）、`Unknown`。層級不是品質評分，而是推論鏈長度的陳述。 |
| 可用性（Availability） | 事實的可讀狀態：`Present`、`NotSupported`、`InsufficientPrivilege`、`ReadError`、`NotApplicable`。 |
| 三態誠實 | 本專案的核心原則：讀不到必須說得出為什麼，不得以 0 或典型值填補。 |
| 讀值可信度下降 | 規則 `R-CPU-04` 的判定語意。在偵測到虛擬層時，硬體直讀的事實由虛擬層提供，因此其可信度下降。這是方法論警告而非硬體異常。 |

### 對帳

| 術語 | 定義 |
|---|---|
| 對帳（Reconciliation） | 比較多個來源對同一件事的陳述。 |
| 規則（Rule） | 一條對帳的單位，表示為 `VerifyRule`。本版共 18 條。 |
| 判定（Verdict） | 對帳的輸出，只有三種：相符、矛盾、無法判定。 |
| 所需事實（Required facts） | 規則的前置輸入。不足時引擎直接判定為無法判定，規則實作不必處理缺值。 |
| 作用域（Scope） | 規則的執行範圍：整機或逐碟（`VerifyScope.Machine`／`VerifyScope.Disk`）。 |
| 證據清單 | 矛盾判定所附的原始事實值清單，使判定可被複核。 |

### 覆蓋

| 術語 | 定義 |
|---|---|
| 覆蓋申報（Coverage report） | 對每個事實鍵申報其是否被對帳規則考慮。 |
| 已覆蓋 | 至少一條規則將其列為輸入。 |
| 明文豁免（Exemption） | 刻意不對帳且附理由。本版共 562 條。 |
| 未覆蓋 | 既無規則考慮亦無豁免。不是錯誤，但必須是一個已知的數字。 |
| 覆蓋率門檻 | 本專案刻意不設定。強制全覆蓋會逼出湊數的規則，其輸出的相符判定是假訊號。 |

### 來源與讀取

| 術語 | 定義 |
|---|---|
| 硬體層 | 繞過作業系統直接與硬體通訊所得的讀值（MSR、PCI 設定空間、SMBus、SMART、NVMe、Super I/O、CMOS）。可信層級為 `Measured`。 |
| 韌體層 | 平台韌體建置期產生、開機時提供的描述（ACPI 表、SMBIOS、UEFI 變數）。可信層級為 `Reported`。 |
| 作業系統層 | 作業系統與驅動程式對硬體的理解（WMI、登錄檔、事件記錄、效能計數器、ETW、X509）。可信層級為 `Reported`。 |
| XsRegProbe | 本專案自寫的白名單唯讀核心模式驅動。白名單指驅動僅處理登記於清單中的暫存器存取請求。 |
| 事實讀取層 | 建立在驅動之上的 Typed 讀取介面，分 MMIO 與 I/O 埠兩條路徑。 |
| SMBus | 記憶體模組的 SPD 與溫度感測器（TSOD）所連接的共享序列匯流排。其存取需要互斥。 |
| MSR | 型號特定暫存器。逐核讀取可用於取得微碼版本、頻率與電源狀態。 |
| 斷路器（Circuit breaker） | 在偵測到重複失敗或逾時後，於本次執行中停止再嘗試某來源的機制。 |
| 降級 | 單一來源失敗時，該組事實以讀取失敗的可用性呈現，其餘事實照常產生的處理方式。 |

### 量測

| 術語 | 定義 |
|---|---|
| 自驗量測 | 在回報數值之前先驗證量測機制本身是否有效。 |
| perft | 西洋棋的節點計數。在本專案中作為西洋棋基準的數學檢核碼。 |
| 誤差範圍 | 量測的統計誤差估計，用於區分訊號與雜訊。 |
| 條件記錄 | 量測時記錄的環境條件（頻率、時序、電源策略、背景負載），跨場次比較的前提。 |
| 場次（Run session） | 深測中心的一次執行單位。 |
| 不可見停頓 | 無法歸因到單一程序或元件的系統停頓。傳統指標（CPU 使用率、磁碟佇列）看不到它。 |

### 輸出與介面

| 術語 | 定義 |
|---|---|
| 快照（Snapshot） | 一次完整事實蒐集的結果，附帶量測時間。 |
| 時間膠囊 | 快照的序列化容器，格式規範為 `docs/spec/snapshot.schema.v1.json`。 |
| 規範化（Canonical） | 序列化格式的性質：同一組事實產生位元組相同的輸出。 |
| 查詢語言 | 用於對快照提出結構化問題的小型語言，規格為 `docs/spec/query-language.v1.md`。七欄位、三運算子、子句之間為 AND。 |
| 硬體變更時間軸 | 兩份快照的比對結果。其本身即為一種對帳（時間上的對帳）。 |
| 審計日誌 | 記錄操作性事件的雜湊鏈日誌，可脫離應用程式驗證。 |
| 判斷的登記表 | 把需要人為決定的分岔登記為資料（決定、理由、條件），使決定的理由不隨人員變動而遺失。 |
| 寫入閘門 | 集中所有寫入操作的模組。任何寫入行為都必須經由它。 |

### 工程

| 術語 | 定義 |
|---|---|
| 守門測試（Guard test） | 驗證一致性的不變式而非功能的測試。用於防止特定類別的缺陷再次出現。 |
| 探針接線死路 | 探針蒐集了資料且接了線，但沒有任何人消費它。不會導致測試失敗，因此必須機械化檢查。 |
| 殭屍前綴 | 已登記的動態家族前綴在原始碼中沒有生產者。由守門測試判定。 |
| 突變測試 | 對原始碼進行微小的語意變更，檢查測試是否失敗。用於發現測試的無效性。 |
| 金標向量 | 由規格手算的位元組級測試輸入，用於驗證對規格的理解而非對實作的理解。 |
| 突變分數 | 突變測試的量化指標。本版目標為 82%。 |
| 可重現基準 | 由掃描原始碼得到的數字，可隨時重跑驗證，而非人工統計。 |
