## 第五十八章　文件地圖與延伸閱讀

### 58.1 本章的用途

本文是專案文件體系的一部分。本章說明本文件與其他文件的關係，並提供依需求查找的路徑。

### 58.2 文件體系

專案的文件依其性質分為四類。

**其一，入口文件。** `README.md`（繁體中文）、`README.zh-CN.md`（簡體中文）與 `README.en.md`（英文）為專案的入口，內容為功能總覽、安裝與使用方式、以及版本沿革。

**其二，本文。** 本白皮書說明設計意圖、資料模型、判定語意、工程約束與事實領域的完整清單。其編排方式為：理念（第一部）、架構（第二部）、對帳（第三部）、功能（第四部）、工程（第五部）、事實領域（第六部）、工程實踐（第七部）、以及附錄 A 至 H。

**其三，規格與方法論文件。** 這些文件記載可獨立引用的規格與方法：

| 文件 | 內容 |
|---|---|
| `docs/spec/query-language.v1.md` | 查詢語言規格 |
| `docs/spec/snapshot.schema.v1.json` | 快照的序列化規格 |
| `docs/spec/METHODOLOGY.md` | 量測方法論 |
| `docs/spec/LIMITATIONS.md` | 已知限制 |
| `docs/spec/CERTIFICATION-PLAN.md` | 認證計畫 |
| `docs/spec/corpus-upload.v1.md` | 語料上傳的規格 |
| `docs/MEASUREMENT-METHODOLOGY.md` | 量測方法論（延伸說明） |
| `docs/DATA-SOVEREIGNTY.md` | 資料主權立場 |
| `docs/DEPLOYMENT.md` | 部署與發行 |
| `docs/EC-RISK-ASSESSMENT.md` | 風險評估 |
| `docs/AGENT_CONTEXT.md` | 貢獻者的工作脈絡 |

**其四，逐輪工作紀錄。** `docs/ROUND-*.md` 形式的文件記載每一輪工作的目標、範圍、量測結果與遺留事項。其價值在於記錄**被否決的路徑**（見 45.5）。

### 58.3 依需求查找

**「我要驗一台二手機器。」** 讀第四十七章（驗機作業流程），並在執行後依第四十九章（報告判讀指南）解讀結果。若出現矛盾，查閱第九章（規則逐條說明）以理解該規則的命題。

**「我要建立設備的稽核基線。」** 讀第四十八章（稽核作業流程）。

**「我要理解為什麼某個欄位沒有值。」** 讀 2.1（三態誠實）與第五十章（疑難排解與常見誤判）。

**「我要理解某條規則的判定邏輯。」** 讀第九章，並對照附錄 C（規則索引）以確認其輸入事實。

**「我要知道某個事實是否被交叉檢查。」** 查附錄 A（該鍵的產生模組）與附錄 D（是否有對應的豁免條目）。若兩者皆無，則該事實未被覆蓋（見 10.3）。

**「我要理解某個動態家族的成員從何而來。」** 查附錄 B（家族與其成員決定方式的申報）。

**「我要擴充功能。」** 讀第五十一章（貢獻者實作指南）與第五十五章（設計決策記錄，以避免重新引入已被否決的設計）。

**「我要引用工具的輸出作為證據。」** 讀 20.4（審計日誌）、48.6（可驗證的匯出）與 46.7（證據可信度風險）。

**「我要理解量測的可靠性。」** 讀第五十三章（量測方法論總覽）與第十三章（自驗量測）。

**「我要理解工具的立場與其不作為。」** 讀 1.4（明確的不作為）與 2.1 至 2.8（八項設計原則）。

### 58.5 本文件的可重現性

本文件的附錄由 `work/wp_gen.py` 從版本控管中的原始碼產生，並由 `work/wp_build.py` 組裝為三個語言版本（見 40.3）。因此當程式碼變更後，重跑產生器即可得到對應的附錄，差異可逐行比對。

此機制的意義與本專案的所有可重現性機制相同：**它使文件與程式碼的漂移成為可偵測的**。若附錄的數字與程式碼不一致，重跑即可發現，而不必等待讀者發現。

### 58.6 文件的維護原則

由本文前述的原則可推得文件維護的三條要求。

**數字必須可重現。** 文件中的統計數字應由產生器產生，而非人工統計（見 26.3、45.6）。

**不作為必須被記錄。** 「刻意不做」的決定應與「尚未做」的工作區分，並記錄其理由（見 17.7、27.3、附錄 D 的規格決策類）。

**被否決的路徑必須被記錄。** 量測結果、未採用的理由與解除條件應一併記錄，使後續的貢獻者不必重新發現（見 23.4、45.5、第五十五章）。
