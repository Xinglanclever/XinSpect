經查證 Anthropic Claude Code CLI 的真實終端實作（包含圓角歡迎框內部留白結構、`✢ ✶ ✻ ✽` 旋轉序列、`⏺` 工具調用標記、` ⎿ ` 樹狀結果縮排，以及 `cwd:` 與幽靈提示互動邏輯），以下為專屬於 **xsc（曦覽終端機 XinSpect Console）** 的完整介面設計規格。

---

**一、Claude Code CLI 查證補充與 xsc 對齊原則**

* **歡迎框內部結構**：真實 Claude Code 歡迎框並非緊湊排列，而是採用「標題行 → 空行 → 3 格縮排說明行 → 空行 → 3 格縮排 `cwd:` 行」的呼吸感結構，外框為單一品牌色圓角細線 `╭─╮ ╰─╯`。
* **Spinner 幀序列與中斷行為**：由 `✢`、`✶`、`✻`、`✽` 四個星芒字元組成往返循環（`✢ → ✶ → ✻ → ✽ → ✻ → ✶`），後接進行式動詞與全形省略號 `…`，括號內以中點 `·` 分隔秒數與 `esc` 中斷提示。按下 `Esc` 時不會清除畫面，而是將狀態定格並還原輸入框。
* **輸出階層（`⏺` 與 `⎿`）**：頂層動作以 `⏺`（U+23FA）頂格開頭；結果行固定縮排 2 格後接 `⎿`（U+23BF）與 2 格空白（即 ` ⎿ `）；若結果有多行，第 2 行起固定縮排 5 格（`     `），與首行文字垂直對齊。每個 `⏺` 區塊結束後必留 1 行空白。

**二、1. xsc 歡迎框逐行內容規格**

歡迎框固定總寬度為 **62 半形欄寬**（含左右框線各 1 欄，內部可用寬度 60 欄），上下與前後段落各留 1 行空白：

```text
╭────────────────────────────────────────────────────────────╮
│ ✻ 歡迎使用 曦覽終端機 xsc v3.16                            │
│   唯讀 ／ 不寫硬體 ／ 不連網                               │
│                                                            │
│   /scan   採集全機硬體事實快照 (WMI · PCI · MSR · LHM)     │
│   /probe  指定單一匯流排或暫存器路徑進行深層探測           │
│   /help   查看完整指令清單，或輸入 /status 檢視探針狀態    │
│                                                            │
│   cwd: C:\Tools\XinSpect\xsc                               │
╰────────────────────────────────────────────────────────────╯

```

**逐行結構與字元對齊規格（共 11 行）：**

* **第 01 行（頂框）**：`╭` + 60 個 `─` + `╯`（品牌紅 `#E30613`）。
* **第 02 行（主標題）**：`│ ` + `✻`（品牌紅）+ `歡迎使用`（預設色）+ `曦覽終端機`（白粗體）+ ` xsc v3.16`（Dim），右側補空白至第 61 欄，第 62 欄為 `│`。
* **第 03 行（安全徽章）**：`│   `（框線後 3 格空白，與上行文字對齊跳過 `✻ `）+ `唯讀`（品牌紅粗體）+ `／`（Dim）+ `不寫硬體`（品牌紅粗體）+ `／`（Dim）+ `不連網`（品牌紅粗體）。
* **第 04 行（呼吸空行）**：`│` + 60 格空白 + `│`。
* **第 05–07 行（快速開始三行指令）**：`│   `（3 格縮排）+ 指令名稱（白粗體，固定佔 8 欄寬：`/scan   `、`/probe  `、`/help   `）+ 說明文字（全行 Dim，其中 `/status` 為預設色不加粗）。
* **第 08 行（呼吸空行）**：`│` + 60 格空白 + `│`。
* **第 09 行（工作目錄）**：`│   `（3 格縮排）+ `cwd: <當前絕對路徑>`（全行 Dim；若路徑超過 52 字元，中間以 `…` 截斷保留頭尾）。
* **第 10 行（底框）**：`╰` + 60 個 `─` + `╯`（品牌紅 `#E30613`）。
* **第 11 行（外距空行）**：純空行，不畫框線。

**三、2. xsc Spinner 動詞清單與格式範例**

**動畫與計時規則：**

* **字元幀序列**：`✢` → `✶` → `✻` → `✽` → `✻` → `✶`（每 120ms 切換一幀，定格完成或中斷時固定停在 `✻`）。
* **動詞輪播**：每次啟動採集隨機抽取 1 個動詞；若單次採集超過 4 秒，每 4 秒平滑切換下一個動詞。

**硬體採集語境動詞清單（共 14 個，俏皮但維持工程嚴謹度）：**

1. `叩問北橋中`（適用：晶片組、Host Bridge 枚舉）
2. `傾聽匯流排脈搏中`（適用：PCI / PCIe 拓撲掃描）
3. `隔窗端詳 Ring0 中`（適用：核心態唯讀探針檢查，呼應「不寫硬體」原則）
4. `凝視 MSR 暫存器中`（適用：CPU 特定模型暫存器讀取）
5. `翻閱 SMBIOS 族譜中`（適用：DMI / 主機板與記憶體條序號解析）
6. `丈量矽晶溫度中`（適用：Thermal Zone 與核心溫度採集）
7. `沿著 PCIe 通道巡邏中`（適用：Link Speed / Width 交涉狀態檢視）
8. `旁聽 WMI 廣播中`（適用：`root\CIMV2` 與 `root\WMI` 命名空間查詢）
9. `屏息讀取電壓軌中`（適用：Vcore / SoC / VDDQ 電壓感測器取樣）
10. `清點針腳電位中`（適用：Super I/O 與 LPC 感測晶片讀取）
11. `校準時脈呼吸中`（適用：BCLK 與有效倍頻計算）
12. `解析 ACPI 表達式中`（適用：DSDT / SSDT 電源管理表對照）
13. `敲門詢問 Named Pipe 中`（適用：連線 `XinSpect.BlueSquadron` 管道）
14. `核對硬體事實清單中`（適用：最終資料結構彙整與交叉驗證）

**格式範例（逐字照抄）：**

```text
✻ 隔窗端詳 Ring0 中… (2s · esc 中斷)

```

```text
✶ 沿著 PCIe 通道巡邏中… (5s · 24 項事實已確認 · esc 中斷)

```

**四、3. 顏色角色表**

全介面嚴格限制為 **4 種視覺層級**，禁止使用藍、綠、黃等額外彩色，背景一律維持終端機原生透明／深色底：

| 視覺層級 | 色碼／ANSI 屬性 | 適用元素（僅限以下項目） | 禁用場景 |
| --- | --- | --- | --- |
| **品牌紅** | `#E30613` (`\x1b[38;2;227;6;19m`) | 1. 歡迎框圓角邊框 `╭─╮╰─╯│`<br>

<br>2. 歡迎框星芒 `✻` 與安全徽章字詞 `唯讀` `不寫硬體` `不連網`<br>

<br>3. 旋轉中的 Spinner 星芒 `✢✶✻✽` 與進行式動詞<br>

<br>4. 正常完成之輸出圓點 `⏺`<br>

<br>5. 提示符 `>` | 禁止用於大段內文、數值表格或錯誤訊息整行塗紅 |
| **白粗體** | `\x1b[1m\x1b[97m` | 1. 歡迎框品牌名 `曦覽終端機`<br>

<br>2. 歡迎框內的快速指令 `/scan` `/probe` `/help`<br>

<br>3. `⏺` 後方的探針名稱（如 `pci.enum`、`msr.read`）<br>

<br>4. 硬體事實中的核心實體名稱與關鍵讀數（如 `Ryzen 7 7800X3D`、`42.0°C`） | 禁止用於單位、括號參數、連接線或狀態註記 |
| **終端預設色** | `\x1b[0m` | 1. 歡迎框的 `歡迎使用` 字樣<br>

<br>2. 使用者在 `> ` 後方實際鍵入的文字<br>

<br>3. ` ⎿ ` 後方的標準事實描述文字与欄位名稱 | 不加粗、不變暗，作為閱讀基準線 |
| **永遠 Dim** | `\x1b[2m` | 1. 版本號 `xsc v3.16`、徽章分隔斜線 `／`、歡迎框指令說明與 `cwd:` 全行<br>

<br>2. Spinner 括號附註 `(2s · esc 中斷)`<br>

<br>3. 結果樹連接符 `⎿`、探針括號參數 `(0x19C)`、十六進位位址與單位<br>

<br>4. **讀不到硬體時的 `⏺` 圓點、`[ -- ]` 標記與未就緒原因全行**<br>

<br>5. 提示符後方的幽靈提示（Ghost Hint）與底部快捷鍵提示 | 絕不用於已成功讀出的關鍵硬體型號 |

**五、4. 事實採集完成的輸出格式（`⏺` 風格）**

採集完成後，Spinner 原地清除並覆寫為 `⏺` 區塊。**誠實硬體事實規則**：成功讀取的項目，`⏺` 為品牌紅；若權限不足、驅動未載入或硬體無回應，`⏺` 改為 **Dim**，並以 `[ -- ]` 標示真實阻礙原因，絕不捏造預設值。

```text
⏺ wmi.sysinfo(root\CIMV2 · SMBIOS Type 1/2/4)
  ⎿  主機板    ROG CROSSHAIR X670E HERO (BIOS 2403 · 唯讀映射)
     處理器    AMD Ryzen 7 7800X3D (8C/16T · Family 19h Model 61h)
     記憶體    65536 MB DDR5-6000 (4 槽已探測 · 2 槽在線)

⏺ pci.enum(Domain 0000:00-FF · Config Space 256B)
  ⎿  00:00.0   Host Bridge        AMD Raphael/Granite Ridge Root Complex
     01:00.0   VGA Compatible     NVIDIA GeForce RTX 4080 [PCIe 4.0 x16 交涉成功]
     04:00.0   Non-Volatile Mem   Samsung PM9A1 NVMe [PCIe 4.0 x4 · 39.0°C]

⏺ msr.read(0x0000019C · IA32_THERM_STATUS)
  ⎿  [ -- ] Ring0 實體通道未就緒（未偵測到已簽章核心驅動，略過直接暫存器讀取）

⏺ rf.pipe(\\.\pipe\XinSpect.BlueSquadron)
  ⎿  [ -- ] 命名管道無回應（背景服務未啟動 · 等待逾時 200ms）

⏺ lhm.sensors(唯讀輪詢 · 零寫入模式)
  ⎿  CPU Package   44.5°C  │  Soc Voltage   1.185 V  │  PPT Limit   88.0 W
     GPU Core      36.0°C  │  VRAM Temp     42.0°C  │  Fan #1      [ -- ] (0 RPM 或停轉)

```

**排版對齊細節：**

* **第 1 層（探針標頭）**：第 1 欄為 `⏺`，第 2 欄空白，接著為**白粗體**探針命名空間（`wmi.sysinfo`、`pci.enum`、`msr.read`、`rf.pipe`、`lhm.sensors`），緊接**不留空白**的 Dim 括號參數 `(...)`。
* **第 2 層（首行結果）**：固定以 ` ⎿ `（2 空白 + Dim `⎿` + 2 空白，共佔 5 欄）開頭。
* **第 2 層（續行結果）**：第 2 行起省略 `⎿`，改為 5 格空白 `     `，確保所有欄位名稱左緣垂直切齊第 6 欄。
* **單行多指標分隔**：同一行並列多組感測器時，使用 ` │ `（前後各 2 空白 + Dim 細直線 `│`）分隔。

**六、5. 提示符與 Ghost Hint（幽靈提示）設計**

提示符區固定位於輸出流最下方，與上一個 `⏺` 輸出區塊間隔 1 行空白，底部附帶 1 行永遠 Dim 的狀態與快捷鍵輔助列。

**狀態 A：初次啟動閒置（尚未輸入任何字元）**

```text
> 輸入 /scan 採集硬體事實，或輸入 pci、msr、temp 篩選探針…
  唯讀模式 · 不寫硬體 · 按 ? 查看快捷鍵

```

* **游標位置**：緊接在 `> `（品牌紅 `>` + 1 格空白）之後的第 3 欄，游標落於「輸」字上方。
* **幽靈提示行為**：`輸入 /scan 採集硬體事實…` 全段為 **Dim**。當使用者按下任何可列印字元、空白鍵或方向鍵的**第一瞬間**，幽靈提示整行立即消失，僅顯示使用者實際鍵入的預設色文字。若使用者將輸入框退格（Backspace）清空至 0 字元，幽靈提示立即重新浮現。

**狀態 B：採集完成後之脈絡感知幽靈提示（Context-Aware Ghost Hint）**
當上一輪採集出現 `[ -- ]` 未就緒項目時，幽靈提示自動切換為針對性建議（依然維持全 Dim）：

```text
> 輸入 /why 查看 [ -- ] 未就緒原因，或輸入 /export 匯出純文字報告…
  唯讀模式 · 已確認 18 項事實 (2 項略過) · 按 ? 查看快捷鍵

```

**狀態 C：按下 `?` 展開之單行極簡快捷提示（不跳視窗、不刷屏）**

```text
> 
  /scan 全機採集 · /pci 匯流排 · /msr 暫存器 · /clear 清空畫面 · esc 中斷或清空輸入 · ctrl+c 離開

```
