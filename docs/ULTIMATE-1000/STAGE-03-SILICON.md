# 極致計畫・階段三｜處理器、晶片組與記憶體

> **規格庫，不是開工指令**：圈了 ID 才開工；接縫不到 API 級不許開工。
> **計數紀律**：只有「新增能力」或「收口」才算一項。
> **本階段 105 項（P3-001–P3-105）**，域碼 8 個。前置：階段一、階段二（表與拓撲的可信基準）。

---

## 一、階段定位

這一階段處理的是**機器最底層的物理事實**：處理器有幾個核心、記憶體插了幾條、裡面的 SPD 怎麼說、微碼是哪一版、頻率為什麼上不去、功耗牆與溫度牆在哪裡。這些事實的共同特性是：**它們由硬體本身決定，不受作業系統樂觀或悲觀的影響**——因此它們同時是整份報告裡最硬的證據，也是最容易因為「讀錯來源」而全盤錯誤的部分。

階段三的兩個技術關鍵：

**其一，多來源對帳是內建的，不是加裝的。**CPU 名稱至少有三個來源（CPUID 字串、SMBIOS Type 4、作業系統），記憶體容量至少三個（SPD、SMBIOS Type 17、作業系統可見量）。它們不一致時，**不一致本身就是最有價值的事實**。

**其二，量測必須自證。**PMU 程式化的每一輪都要驗證寫入後回讀一致；頻寬換算要在回報前用已知大小的負載自驗。這一階段不接受「看起來合理」的數字。

---

## 二、完美判準（Gate）

1. **處理器識別三來源並列**：CPUID、SMBIOS、作業系統三者的品牌字串、核心數、執行緒數並列，不一致具名（P3-001）。
2. **微碼雙來源對帳**：MSR 與登錄檔版本互校，不一致時兩者都輸出（P3-021）。
3. **SPD 解碼出處到位移級**：DDR5 SPD Hub 的每個欄位標出位移與位寬，且以真實模組樣本為 golden 值（P3-043）。
4. **頻寬自驗**：任何頻寬數字在回報前以已知大小的負載自驗（P3-046）。
5. **PMU 程式化可還原**：任何計數器設定在 `finally` 還原，並逐輪驗證寫入後回讀一致（P3-031）。
6. **牆的陳述而非判決**：頻率、功耗、溫度、電流牆逐項陳述其來源與限制條件，不輸出「被降頻」的結論（P3-085）。
7. **ECC 三層分離**：硬體支援、已啟用、已偵測錯誤三件事分開陳述（P3-073）。
8. **拓撲一致**：快取、核心、NUMA、記憶體通道四者的拓撲陳述彼此一致，衝突時列出兩側（P3-061）。

## 四、完整規格（九欄）

### ★ P3-031｜PMU 程式化與還原驗證

**目標**：用效能監視單元量出可複核的事件計數，且保證**不留下被改動的硬體狀態**。

**接縫**：`IA32_PERFEVTSEL*`／`IA32_PMC*`（MSR，經白名單唯讀驅動的受控寫入路徑）＋ `IA32_FIXED_CTR_CTRL`；固定功能計數器數量依 CPUID 0xA 報告決定（2／3／4 個的架構都存在），不寫死。

**方法**：每次量測為「保存原值 → 設定事件與計數器 → 讀取 → 還原」的封閉序列；還原置於 `finally`；**每一輪都驗證寫入後回讀一致**，不一致時該輪結果標為無效並輸出差異，不以無效值參與統計。事件編碼以規格出處標註，未知事件碼拒絕設定而非猜測。

**輸出鍵**：`pmu.fixed.count`、`pmu.fixed.{n}`、`pmu.program.ok`、`pmu.restore.ok`、`pmu.event.{name}`。

**三態行為**：無 PMU 或 CPUID 0xA 未報告 → `NotSupported`；MSR 不可寫 → `InsufficientPrivilege`（**唯讀計數仍可輸出**）；寫入後回讀不一致 → `ReadError` 附期望與實測；可讀可取但無事件 → `NotApplicable`。

**誠實界線**：本項量的是**事件計數**，不是「效能好壞」；不提供跨機比較，因為計數語意隨微架構改變。也**不**在無法還原的路徑上做任何量測——寧可放棄一次量測。

**守門**：性質測試（模式：不變式）——任意設定序列後，還原值必等於初始值（以假 MSR 層驗證）；另以真機實測記錄 `pmu.restore.ok=true`。**正對照**：故意移除還原步驟，測試須紅燈。

**依賴**：P1-001（骨架）、P3-006（MSR 讀取層）。

**驗收**：假層的還原性質全綠；真機實測記錄隨版本保存；未能驗證還原的機器列入未施測聲明。

### ★ P3-043｜DDR5 SPD 解碼與三來源對帳

**目標**：把每條模組的 SPD 內容解成事實，並與 SMBIOS、作業系統可見量三方對帳。

**接縫**：SPD Hub（I3C／SMBus 路徑，唯讀）與 SMBIOS Type 17；解碼器為純函式，輸入為 SPD 位元組陣列。

**方法**：依 JEDEC DDR5 SPD 規範解析（廠商、型號、序號、容量、組織、時序、電壓、溫度感測、模組位置）；**每個欄位標位移與位寬**；序號與型號屬 L1，匯出時遮蔽。與 SMBIOS 及作業系統可見量比對：容量、速度、通道配置三項逐條並列。

**輸出鍵**：`spd.{n}.vendor`、`spd.{n}.part`、`spd.{n}.size`、`spd.{n}.speed`、`spd.{n}.rank`、`mem.cross.capacity`、`mem.cross.speed`。

**三態行為**：無 SPD 通道 → `NotSupported`；通道存在但模組未回 → `ReadError` 附 SMBus 位址；欄位為 0 但**合法**（例如某些模組的溫度欄位）→ `Present` 且值為 0（**0 就是 0**，不得當成缺）；規範未收錄的欄位 → `Unknown` 並列出位移。

**誠實界線**：SPD 描述的是**模組自稱**，不是實測能力；本項不驗證模組是否為原廠、不判斷序號真偽（假容量驗證在階段四）。序號與型號遮蔽後仍可交叉對帳。

**守門**：金標／往返（模式：解碼器）——以真實模組的 SPD 傾印為 golden；並以「位移錯一格的合成資料」驗證測試會紅（**合成資料只用來驗證測試有牙，不用來當 golden**）。

**依賴**：P1-023、P2-023（SMBIOS Type 17）。

**驗收**：真機每條模組與 SMBIOS 容量一致或差異具名；位移級出處覆蓋率 100%（不在規範內的欄位除外並列出）。

## 六、誠實界線與明文不做

**不做**：

| 不做 | 理由 | 解除條件 |
|---|---|---|
| 寫入 MSR 做超頻或調整 | 唯讀立場；且不可回復的硬體狀態風險 | 無 |
| 破壞性記憶體壓力測試 | 可能導致資料損毀 | 無 |
| 錯誤注入 | 與唯讀衝突 | 無 |
| 以 0 填補讀不到的感測值 | 三態違反 | 無 |
| 跨機頻率／效能排名 | 計數語意隨微架構改變，比較無效 | 若提供同型號同微碼的嚴格配對機制 |

**本階段沒有證明的事**：階段三的重量測（頻寬、延遲、PMU 事件）證明「這樣量、在這個條件下、得到這個數字」，**不證明「這台機器比較快或比較慢」**。所有比較性輸出在階段八以量測方法論的形式補上條件；階段三本身只交付事實與其出處。
