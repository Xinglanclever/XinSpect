# 極致計畫・階段四｜儲存、檔案系統與資料完整性

> **規格庫，不是開工指令**：圈了 ID 才開工；接縫不到 API 級不許開工。
> **計數紀律**：只有「新增能力」或「收口」才算一項。
> **本階段 105 項（P4-001–P4-105）**，域碼 9 個。前置：階段一、階段三。

---

## 一、階段定位

儲存是**資料唯一的容器**，也是驗機最常見的爭議現場：二手機的 SSD 是否被換過、宣稱的容量是否為真、通電時數是否被重設、韌體是否被改寫、壞軌是否已出現。這一階段把這些爭議全部轉成可讀的事實與可對照的落差。

階段四有三個特性：

**其一，逐裝置而非整機。**儲存的健康狀態本質上是逐顆碟的；任何「整機儲存健康」的數字都是聚合，而聚合會隱藏單顆的問題。因此本階段的輸出以逐碟為單位，聚合只作為索引。

**其二，0 是合法值。**磨損 0%、延遲 0 ms、重試 0 次都是正常且合法的讀值；把它們當成「缺」是本領域最容易犯的錯。本階段所有計數欄位都必須區分「值為 0」與「讀不到」。

**其三，覆蓋率要申報。**提供者沒給的欄位要**數出並具名**，並附一句「空值不代表 0」。這是三態誠實在本階段的具體落實。

---

## 二、完美判準（Gate）

1. **逐碟逐欄，0 不等於缺**：所有計數欄位可區分 0 與不可得；覆蓋欄位具名列出未提供者（P4-001）。
2. **容量真偽可驗**：以寫入驗證（受控、可回復）證明宣稱容量；不通過者具名列出實際可寫範圍（P4-075）。
3. **NVMe 全欄位**：健康、錯誤紀錄、命名空間、溫度、WCTEMP、佇列深度齊備，未支援者具名（P4-023）。
4. **完整性可比對**：可輸出逐檔／逐區雜湊與前次基線比對，變更逐項列出（P4-063）。
5. **安全擦除唯讀陳述**：只陳述支援與狀態，**不執行**任何破壞性指令（P4-083）。
6. **檔案鑑識離線可重跑**：鑑識項以使用者提供的映像為輸入，同一輸入必得同一輸出（P4-035）。
7. **壽命模型附不確定性**：任何剩餘壽命估計必須附區間與依據，不得輸出單一數字（P4-091）。
8. **與階段八介面一致**：儲存深測的量測條件與階段八方法論同格式（P4-099）。

## 四、完整規格（九欄）

### ★ P4-001｜儲存可靠性全欄位與覆蓋申報

**目標**：對每顆碟取得提供者能給的每一個可靠性計數器，並**具名列出提供者沒給的欄位**，且區分 0 與缺。

**接縫**：`MSFT_StorageReliabilityCounter` 關聯（**直接查會回空，必須走 `ManagementObject.GetRelated`**；自組 `ASSOCIATORS OF` WQL 會因 `ObjectId` 含反斜線引號而失敗）＋ `MSFT_PhysicalDisk`。

**方法**：逐碟列舉 → 逐欄位取值 → 對每個欄位記錄三態與來源 → 彙總覆蓋率。已知的 19 欄位為一組，欄位集本身由關聯的屬性清單動態決定（**不寫死**，提供者新增欄位時自動納入）。

**輸出鍵**：`storage.reliability.{id}.<欄位>`（含 `wear`、`power_on_hours`、`read_errors_total`、`temperature_max` 等）、`storage.reliability.{id}.coverage`（未提供欄位清單＋「空值不代表 0」聲明）、`storage.reliability.count`。

**三態行為**：來源不可用 → 一筆 `ReadError` 並帶 `ManagementException` 訊息；來源可用但 0 筆 → `NotApplicable`（**環境狀態不是缺陷**）；欄位值為 0 → `Present` 且值為 0；欄位不在關聯中 → 列入 `coverage` 並標 `Unknown`。

**誠實界線**：本項輸出的是**提供者自稱**的計數器；不推論碟的健康結論、不預測剩餘壽命（後者見 P4-091）。`temperature_max` 回 0 時照實呈現為 0，不假設「0 表示無感測器」。

**守門**：基線守門（模式：數字）——以假來源驗證 19 欄的解析與覆蓋計算；**並含一條時序迴歸測試**：把「先判可用性再讀取」的舊順序改回去，必須紅燈（歷史缺陷，見白皮書第六十四章）。

**依賴**：P1-001、P1-019（狀態判定時序）。

**驗收**：真機輸出與手動 `Get-PhysicalDisk` 對照一致；`coverage` 內容與實際提供者差異相符；時序迴歸測試有牙。

### ★ P4-075｜容量真偽寫入驗證

**目標**：證明一顆碟的**實際可寫範圍**與它宣稱的容量是否相符——這是二手機最常見的造假點，也是最不能靠「讀」回答的問題。

**接縫**：受控寫入路徑（**經寫入閘門**，P1-067）；寫入範圍限於使用者指定的檔案或專用測試區，且每一筆寫入可回復（刪除／還原）。

**方法**：以遞增偏移寫入帶校驗的測試樣式（含偽隨機序列與固定樣式兩種，以偵測「回繞寫入」與「靜默丟棄」）→ 讀回比對 → 記錄第一個不一致的偏移 → 估算實際容量。**預設僅在明確指定的空閒區域執行**，磁碟使用率超過閾值時拒絕執行並說明原因。

**輸出鍵**：`cap.declared`、`cap.writable.max`、`cap.first_mismatch`、`cap.result`（相符／不足／無法判定）、`cap.write.bytes`（實際寫入量，供使用者評估磨損成本）。

**三態行為**：碟不可寫（唯讀、防寫、系統碟未經同意）→ `NotApplicable` 並附原因；寫入失敗 → `ReadError` 附錯誤碼；樣式寫入成功且讀回一致 → `Present`；樣式一致但容量不足宣稱 → `Present` 且 `cap.result=不足`。

**誠實界線**：本項是**唯一寫入硬體的常規功能之一**，因此（a）必須 opt-in；（b）必須回報實際寫入量；（c）不對系統碟執行；（d）結果只說「可寫範圍與宣稱是否相符」，**不判定是否為仿冒品**。

**守門**：掃描守門（模式：介面契約）——本項的寫入必須全部經寫入閘門，且測試斷言其無其他寫入路徑；另以假裝置（回繞寫入的模擬器）驗證偵測能力。

**依賴**：P1-067（寫入閘門）、P1-068（寫入記帳）、P4-003（容量與型號）。

**驗收**：真機正常碟得 `相符`；模擬回繞碟得 `不足` 並給出第一個不一致偏移；每次執行後寫入帳本有對應紀錄。

## 六、誠實界線與明文不做

**不做**：

| 不做 | 理由 | 解除條件 |
|---|---|---|
| 固件更新、安全擦除、格式化的執行 | 破壞性且不可回復 | 無（僅陳述支援與狀態） |
| 原始檔案系統內容雕刻（carving） | 屬另一類產品；且需大量寫入暫存 | 若提供唯讀且可驗證的雕刻路徑 |
| 對系統碟執行容量驗證 | 風險不可接受 | 無 |
| 判定硬碟是否為仿冒品 | 需原廠資料庫與實體判準；本專案只陳述落差 | 若原廠提供可比對的公開特徵集 |
| 以單一數字給剩餘壽命 | 不確定性必須隨估計一起輸出 | 無 |

**本階段沒有證明的事**：階段四證明「這顆碟現在回報什麼、它實際能寫到哪裡、資料有沒有被改過」，**不證明「這顆碟還能用多久」**——壽命項（P4-091）輸出的是區間與假設，不是保證。任何把 `life.estimate` 當成保固判定的用法，都超出本階段的能力範圍。
