# 極致計畫・階段九｜平台化、呈現、報告與外部介面

> **規格庫，不是開工指令**：圈了 ID 才開工；接縫不到 API 級不許開工。
> **計數紀律**：只有「新增能力」或「收口」才算一項。
> **本階段 105 項（P9-001–P9-105）**，域碼 9 個。前置：階段一、六、七、八。

---

## 一、階段定位

前八階段產生事實；階段九**把事實交到使用者手上**。這一階段的判準因此不是「有沒有功能」，而是**「同一個事實在不同出口是否一致」**：畫面上看到的、匯出的、命令列查到的、本機介面傳出去的，必須是同一份。

專案已有一條貫穿架構的規則處理這件事：**所有輸出消費同一個事實模型**。階段九把這條規則展開成 105 項可驗收的工作，其中最關鍵的三件是：

1. **逐值溯源**：任何一個數字都能回答「它從哪來、什麼時候讀的、讀不到時為什麼」。
2. **出口一致守門**：四個出口的內容由同一個模型派生，掃描守門確保沒有第二份格式化邏輯。
3. **監聽預設關閉**：任何會讓機器「開始聽」的功能預設不啟動，由使用者決定開啟。

---

## 二、完美判準（Gate）

1. **逐值溯源可達**：任一輸出值可追到來源、時間、三態與出處（P9-002）。
2. **出口一致守門**：畫面／匯出／命令列／本機介面四者由同一模型派生，無第二份邏輯（P9-015、P9-041、P9-053）。
3. **監聽預設不啟動**：任何監聽通路預設關閉，開啟需明示同意，且有掃描守門（P9-036、P9-042）。
4. **報告可重現**：同一份快照產生同一份報告（雜湊相同）（P9-026）。
5. **查詢錯誤不偽裝成空結果**：語法錯誤回傳錯誤（P9-047）。
6. **精靈只組裝，不判斷**：情境精靈是既有事實的組裝層，不新增判決（P9-064）。
7. **自動化不新增常駐**：所有自動化由使用者觸發或使用者提供的排程觸發（P9-071）。
8. **圖表與資料一致**：圖表由事實派生，且有守門確保不漂移（P9-097）。

## 四、完整規格（九欄）

### ★ P9-002｜逐值溯源卡

**目標**：對任何一個輸出值，回答四個問題——**它從哪裡來、什麼時候讀的、讀不到時為什麼、依哪一條出處解出來的**。

**接縫**：事實模型（來源、可信層級、可用性、量測時間）＋ 出處鏈（階段一）＋ 呈現層的通用元件。四個出口共用同一個溯源元件，不各自實作。

**方法**：以事實的鍵為輸入 → 組裝溯源卡（來源識別、讀取時間、可用性與原因、規格出處、衍生鏈）→ 呈現可展開的層級。衍生事實（由其他事實推出者）顯示其輸入事實與推導規則。

**輸出鍵**：`ui.provenance.available`、`ui.provenance.fields`、`ui.provenance.derivation`（衍生鏈）、`ui.provenance.gap`（缺出處的欄位）。

**三態行為**：來源可回溯 → `Present`；來源不明（例如匯入資料未附來源）→ `Unknown` 並**明示來源不明**，不顯示空欄；衍生鏈有缺 → `Present` 且 `gap` 非空；出處未對準 → 依階段一規則不出值。

**誠實界線**：溯源卡顯示的是**本工具所記錄的來源**，不是來源本身的真實性；若來源本身說謊（例如硬體回報假值），溯源卡只會忠實顯示「這個值來自那個來源」。

**守門**：掃描守門（模式：介面契約）——四個出口必須都使用同一個溯源元件，掃描原始碼確保沒有第二份實作；正對照：在匯出端另寫一份簡化溯源即紅燈。

**依賴**：P1-027（出處與值對應）、P1-021（未讀取原因）。

**驗收**：四個出口對同一事實的溯源內容一致；構造一個無來源的匯入事實，溯源卡明示來源不明；匯出端另寫實作會被守門擋下。

### ★ P9-046｜查詢語言

**目標**：讓使用者能用一句話問出「符合條件的事實」，且**答不出來時說出為什麼**。

**接縫**：查詢解析器（純函式）＋ 事實集合；語法規格見 `docs/spec/query-language.v1.md`。

**方法**：解析為條件樹 → 於事實集合求值 → 輸出相符項與**求值統計**（掃描項數、相符項數、被三態排除的項數）。**語法錯誤回傳錯誤與位置**，不回傳空結果（把查錯偽裝成空結果屬誠實違反）。欄位與運算子支援清單書面公告，未支援者明示未支援。

**輸出鍵**：`query.result.count`、`query.result.items`、`query.evaluated`、`query.excluded.state`（因三態被排除的項數）、`query.error`（語法錯誤位置與訊息）。

**三態行為**：語法錯誤 → `query.error` 有值且結果為空（**區分「錯誤」與「沒有結果」**）；查詢語法正確但零相符 → `Present` 且計數為 0；查詢用到的欄位不存在 → 列出未知欄位而非略過。

**誠實界線**：查詢只涵蓋**已收集的事實**；未收集的事實不會出現，也不會以「不存在」回答。查詢不觸發新的硬體讀取（避免查詢變成掃描）。

**守門**：金標（模式：解碼器）——語法與結果的 golden 對組；性質測試（恆真與恆假條件、重複條件的結合律）；正對照：把語法錯誤改成回傳空結果，測試須紅燈。

**依賴**：P1-077（鍵目錄）、P9-049（索引）。

**驗收**：語法錯誤與零結果可區分；未知欄位被列出；`query.excluded.state` 與實際三態統計一致。

## 六、誠實界線與明文不做

**不做**：

| 不做 | 理由 | 解除條件 |
|---|---|---|
| 常駐服務、背景監控、自動上報 | 與零常駐、零上傳衝突 | 無 |
| 以 Web 服務形式提供 SaaS | 與免安裝、資料主權衝突 | 無 |
| 對外可用的 REST 範例集 | 隨附可用範例等於承諾未承諾的端點 | 若端點規格正式納入承諾範圍 |
| 行動裝置或跨平台用戶端 | 需要另一套呈現與權限模型 | 無 |
| 在報告中輸出判決或評分 | 判定只有狀態，判讀留給使用者 | 無 |

**本階段沒有證明的事**：階段九證明「事實可以被看到、被查、被匯出、被整合」，**不證明「看到的就是全部」**。任何出口的完整性受限於其來源階段的覆蓋率；因此每一份報告都附缺口申報（P9-104、P6-013 類），讓讀者知道哪些事實不在其中。
