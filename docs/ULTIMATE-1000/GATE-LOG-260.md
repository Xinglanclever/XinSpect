## 一、P2-105：階段二矩陣對實作的對帳（`fw.doc.reconcile`）

**這一項回答「這份建置與階段二的規格對到哪裡」，不回答「階段二做完了沒」。**

矩陣有 105 項、**114 把鍵**（一列可以宣告多把：P2-014 的 `ac.spcr`／`ac.dbg2.*`、
P2-017 的 `ac.tpm2`／`ac.table.wpbt`、P2-029 的兩半）。本輪把三種狀態的計數收斂成一把事實：

| 狀態 | 意思 | 本輪 |
|---|---|---:|
| `ok:` | 規格鍵與實作鍵同名 | 65 |
| `alias:` | 語意相同、實作早就在（名字不同） | 24 |
| `todo:` | 尚未實作 | 25 |
| **合計** |  | **114** |

**為什麼數字是編譯期常數：** 發佈版是單一執行檔，身邊沒有 `docs/`。執行期讀一份不存在的
文件會得到「0 項、0 把鍵」，而 0 在畫面上會被讀成「全部完成」——那正是
`FactKeyCatalog` 之所以是編譯期目錄的同一個教訓。**掃不到不得冒充沒有問題。**

**代價是常數會腐爛**（做完一項、改了矩陣，卻忘了改常數），所以新增
`FirmwareDocReconcileTests` 逐列重算矩陣：105 列、欄位數 9、只認 `| ★?P2-nnn |` 開頭，
以全形斜線切開實作鍵欄計數。文件改了而常數沒改，紅燈。

**它不給百分比。** 24 把別名是「規格換了名字、實作早就在」，把它們與新寫的實作
混成一個完成率，會讓「改名」看起來像「完工」。

## 二、`<FileVersion>` 是版號的第四處，而它落後了一版

**已出貨的 v2.85 執行檔，檔案內容裡顯示的「檔案版本」是 `2.84.0.0`：**

```
publish-2.85\XinSpect.exe   33,680,171 bytes
  FileVersion    = 2.84.0.0
  ProductVersion = 2.85+8d1098631c0db41373d8bf8da052d18b746281ea
```

`<Version>` 改了、`<FileVersion>` 沒改。v2.83 時兩者一致，是 2.85 漏的。
**它不會讓程式壞掉、也不會讓任何測試紅**——只會讓使用者在檔案內容裡看到一個少一版的號碼，
而那正是他唯一看得到的地方。既有的 `ChangelogTests` 守著紀錄、徽章與關於頁三者，
正好從它旁邊走過去。

本輪把 `FileVersion` 修為 `2.85.0.0`，並加一條守門：`FileVersion` 的前三段必須等於
`<Version>`。下一版（2.86）發版時，這條會強迫兩者一起動。

## 四、本機實測（2026-10-18，這一輪真的跑過的）

```
TBS 服務：Get-Service TBS → 不存在（不是停止，是沒有這個服務）
ACPI 表列：DBGP MCFG FACP SRAT MSCT SLIT DMAR APIC HPET FPDT FIDT MIGT PCAT PCCT RASF
           SVOS WDDT OEM4 OEM1 SSDT NITR SSDT LPIT WSMT SSDT DBG2 BGRT WPBT TPM2
           → 29 個表項目，沒有 HMAT（也沒有 NFIT／PPTT）
EFI 變數：GetFirmwareEnvironmentVariableExW("BootOrder") → 0 bytes、GetLastError 1314
           （ERROR_PRIVILEGE_NOT_HELD），而該行程 IsInRole(Administrator) = True
ring0：服務清單沒有 XinSpect／WinRing0 項目；XinSpect.sys 只在舊的 publish 目錄裡
規格原文：uefi.org 被 DNS 解析到 198.18.0.12（保留位址）；DMTF 的 PDF 也取不到
```

**兩個容易誤讀的地方：**

1. **1314 不是「這台機器不支援 UEFI」。** 韌體是 UEFI（`BiosFirmwareType=Uefi`）、TPM2 與
   WPBT 表都在。1314 說的是**權杖沒有啟用 `SeSystemEnvironmentPrivilege`**——那是
   `AdjustTokenPrivileges` 可以解的，與 P2-082 的「沒有列舉 API」是**兩件不同的事**：
   前者擋住 P2-081／089（要讀特定變數），後者擋住 P2-082／090（要列舉）。
2. **HMAT 缺席不等於讀取失敗。** 表列本身是成功的。缺席是「這台消費級平台沒有提供」——
   就算現在寫好解碼器，本機只會得到 `NotApplicable`，**拿不到一次真機 golden**。
