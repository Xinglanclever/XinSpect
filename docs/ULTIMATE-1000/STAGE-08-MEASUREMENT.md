# 極致計畫・階段八｜量測科學與深測

> **規格庫，不是開工指令**：圈了 ID 才開工；接縫不到 API 級不許開工。
> **計數紀律**：只有「新增能力」或「收口」才算一項。
> **本階段 105 項（P8-001–P8-105）**，域碼 9 個。前置：階段一、三、四、五。

---

## 一、階段定位

前七階段輸出的是**狀態事實**（存在什麼、是什麼版本、在哪個狀態）；階段八輸出的是**量測事實**（做了什麼事、量到多少、在什麼條件下）。這兩類事實的性質不同，因此判準也不同：

- 狀態事實錯了，會與其他來源矛盾而暴露；
- **量測事實錯了，如果沒有自驗機制，它不會矛盾——它只會是一個看起來合理的數字。**

所以本階段全部 105 項都被兩條規則約束：

**規則一：量測必須自證。**西洋棋基準以數學檢核（perft 節點數）作為正確性錨；頻寬換算在回報前先以已知大小的負載自驗；PMU 每一輪驗證寫入後回讀一致。凡量測項，都要能回答「你怎麼知道自己量對了」。

**規則二：條件必須隨數字輸出。**同一個數字在不同電源計畫、不同背景負載、不同暖機狀態下不可比較。因此每一項量測的輸出都包含條件，跨機或跨時間的比較只在條件一致時成立（P8-001）。

---

## 二、完美判準（Gate）

1. **每個量測項都有自驗方法**，且該方法可被第三方重跑（P8-098–P8-105）。
2. **條件隨數字輸出**，且條件欄位為必填（無條件不得回報）（P8-001）。
3. **暖機與冷啟分離**：冷啟動與暖機後的結果分別輸出，不合併（P8-002）。
4. **統計而非單點**：每項量測輸出分布（最小／中位／最大／樣本數），不以單一值代表（P8-003）。
5. **環境干擾可見**：背景負載、電源計畫、散熱狀態列入條件（P8-004）。
6. **不可比較時明說**：跨機或跨時間比較在條件不符時輸出「不可比較」而非數字（P8-005）。
7. **量測本身有成本宣告**：執行前告知 CPU、磁碟、時間成本（P8-006）。

## 四、完整規格（九欄）

### ★ P8-001｜量測條件與限制格式

**目標**：定義一個**必填的條件欄位集**，使任何量測數字都附帶「這是在什麼情況下量的」，且缺條件時不得回報數字。

**接縫**：共用結構（量測條件物件）＋ 所有量測項的輸出整合點。條件物件至少含：電源計畫、背景負載摘要、暖機狀態、散熱狀態、量測時間窗、樣本數、工具版本、微碼版本。

**方法**：量測前收集條件 → 與數字一同輸出 → 匯出時條件為必填欄位（缺條件則匯出失敗並說明缺哪一欄）。**條件本身也是事實**，因此附出處與三態。

**輸出鍵**：`meas.conditions`（結構化條件）、`meas.conditions.missing`（缺欄位清單）、`meas.comparable`（與另一筆量測是否可比較）。

**三態行為**：條件不可得（如需管理員權限的電源計畫查詢）→ `Unknown` 且**允許量測但標示不可比較**；條件齊備 → `Present`；條件欄位存在但值為空 → 列入 `missing`。

**誠實界線**：條件齊備**不等於**兩次量測可比較——背景負載無法完全列舉，因此 `meas.comparable` 在背景差異顯著時輸出「不可比較」而非「相同條件」。

**守門**：掃描守門（模式：介面契約）——所有量測輸出型別必須包含條件欄位，掃描原始碼驗證無例外；正對照：移除某量測項的條件即紅燈。

**依賴**：P2-049（微碼版本）、P6-009（電源計畫）、P8-003（統計）。

**驗收**：全量測項通過條件必填守門；缺條件時匯出失敗並指名欄位；`meas.comparable` 在刻意改變電源計畫後輸出不可比較。

### ★ P8-098｜自驗量測框架（perft／checksum／回讀）

**目標**：為「量測正確性」建立三個可重用的自驗機制，使量測數字不是自我宣稱，而是可被檢核。

**接縫**：三個機制各自為獨立元件，供各量測項使用：**(a) 數學檢核**——以可獨立計算的參考值驗證引擎輸出（西洋棋以 perft 節點數）；**(b) 往返／校驗**——以已知大小的負載驗證換算（頻寬、壓縮率）；**(c) 回讀一致**——對受控硬體設定驗證寫入後回讀（PMU）。

**方法**：每個使用自驗的量測項在回報前跑一次自驗；自驗失敗時**不輸出量測值**，而是輸出自驗失敗的事實（`selfverify.failed`）與差異。自驗成本納入量測條件（P8-006）。

**輸出鍵**：`selfverify.{kind}.ok`、`selfverify.{kind}.expected`／`selfverify.{kind}.actual`、`selfverify.failed.count`、`selfverify.kind`（`math`／`roundtrip`／`readback`）。

**三態行為**：自驗通過 → `Present`；自驗失敗 → `Present` 但量測值標為無效並輸出差異；自驗不可用於該項 → `NotApplicable`（**且該量測項不得對外宣稱已自驗**）。

**誠實界線**：自驗證明「量測管線在已知輸入上正確」，**不證明「這個量測在物理上反映真實效能」**。例如 perft 證明搜尋引擎正確，不證明它代表真實棋力；後者的界線寫入各量測項的誠實界線欄。

**守門**：金標（模式：解碼器）——三種自驗各以已知答案驗證；**且含「自驗失敗時量測值不得輸出」的守門**（正對照：注入一個錯誤的參考值，必須造成量測值被標為無效）。

**依賴**：P8-001、P1-057（基線守門）。

**驗收**：三種自驗的已知答案全綠；注入錯誤參考值時量測值確實被封鎖；未自驗項目在輸出中明示。

## 六、誠實界線與明文不做

**不做**：

| 不做 | 理由 | 解除條件 |
|---|---|---|
| 破壞性壓力測試（記憶體、碟、電源循環） | 可能導致資料損毀或硬體損傷 | 無 |
| 外網速度測試與第三方基準服務 | 需網路 | 由使用者在允許連線的環境自行執行 |
| 效能排名與「這台比那台快」的結論 | 條件不可比時結論無意義 | 若提供嚴格配對（同型號、同微碼、同散熱）的比較機制 |
| 故障注入 | 與唯讀衝突 | 無 |
| 以單一數字代表效能 | 必須附分布與條件 | 無 |

**本階段沒有證明的事**：階段八證明「在這些條件下，這件事的表現是這樣」，**不證明「這台機器好用或不好用」**。任何跨機、跨時間、跨版本的比較，只有在條件一致時才輸出數字，否則輸出「不可比較」——這是本階段最重要的一個輸出值。
