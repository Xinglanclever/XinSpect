# 極致計畫・階段七｜安全、取證、離線鑑識與合規

> **規格庫，不是開工指令**：圈了 ID 才開工；接縫不到 API 級不許開工。
> **計數紀律**：只有「新增能力」或「收口」才算一項。
> **本階段 105 項（P7-001–P7-105）**，域碼 9 個。前置：階段一、二、四、六。

---

## 一、階段定位

階段七處理的是**「這台機器在信任與痕跡上呈現什麼」**。它與前六階段最大的差別是：這裡最容易出現「結論」，而本專案的立場是**只出事實**。

因此本階段有一條貫穿全部 105 項的規則：**每一項輸出的都是狀態、存在性、計數、落差或時間線，沒有一項輸出「安全／不安全」、「乾淨／被入侵」的判決。**這不是保守，而是可複核性：一個事實可以被第三方重跑，一個判決只能被相信。

階段七也是離線鑑識（OF 域）的所在。離線模式的價值在於：**同一套解碼層、同一套六態、同一套守門**，只是輸入從活系統換成使用者提供的映像、日誌或傾印。這使得鑑識結果可用同一組測試驗證。

---

## 二、完美判準（Gate）

1. **零判決**：全階段輸出不得含「安全／不安全」「惡意／乾淨」「合規／不合規」的結論詞；由字串掃描守門（P7-014、P7-085）。
2. **離線唯讀保證機制化**：離線掃描器的寫入禁令由掃描守門釘住，且有正對照（P7-051、P7-064）。
3. **不需符號的那一半**：傾印分析只輸出無需符號的部分，並明示哪些區塊讀不到（P7-054、P7-056）。
4. **稽核可獨立驗證**：稽核鏈的驗證不依賴被驗證的物件（P7-067、P7-072）。
5. **DMA 與虛擬化防護逐項陳述**：IOMMU、核心 DMA 保護、VBS、機密運算逐項狀態，不合成分數（P7-027、P7-039）。
6. **持久化面完整盤點**：自動啟動、排程、服務、映像劫持、分層服務提供者逐面陳述（P7-087–P7-092）。
7. **證據包可驗**：格式、雜湊、manifest 與審計鏈互驗（P7-097–P7-100）。
8. **金鑰值不出現**：任何憑證或金鑰僅輸出存在性，L3 禁項由測試釘死（P7-048）。

## 四、完整規格（九欄）

### ★ P7-051｜離線掃描唯讀保證

**目標**：讓「離線掃描不會改動原始映像」不只是承諾，而是**機制**——由掃描守門釘住，並以正對照證明它會紅燈。

**接縫**：離線掃描器（實作階段一的掃描骨架）＋ 掃描守門（原始碼層檢查）＋ 檔案系統層的唯讀開啟路徑。輸入為使用者提供的映像、蜂巢、事件日誌或傾印。

**方法**：所有離線輸入以唯讀方式開啟；骨架的 `finally` 還原任何暫態；掃描守門掃描離線掃描器原始碼，禁止出現寫入 API（`File.Write*`、`CreateFile` 帶寫入旗標、`SetFileTime`、`DeleteFile` 等）與暫存檔寫入路徑。掃描前後對輸入檔案計算雜湊並比對（**輸入雜湊不變**是這一項的核心輸出）。

**輸出鍵**：`off.mount.kind`、`off.readonly.ok`、`off.input.hash.before`／`off.input.hash.after`、`off.input.unchanged`、`off.write.attempts`（應恆為 0）。

**三態行為**：輸入不可讀 → `ReadError`；輸入格式不支援 → `NotApplicable` 附格式前綴；可讀但需外部解碼器 → `Present` 且列出未解得部分；輸入雜湊前後不一致 → **紅燈級事件**（`off.input.unchanged=false`，並輸出兩個雜湊）。

**誠實界線**：唯讀保證涵蓋**本專案自身的寫入**；不涵蓋作業系統快取或第三方工具的行為。本項也不保證輸入本身的真實性——那是證據鏈的問題（P7-100）。

**守門**：掃描守門（模式：介面契約）＋正對照：在離線掃描器內臨時加入一次寫入呼叫，測試必須紅燈並指名該呼叫；另加執行期守門：每次離線掃描前後自動比對輸入雜湊。

**依賴**：P1-001（骨架）、P1-008（唯讀保證守門）、P1-009（離線輸入接縫）。

**驗收**：正對照紅燈；真機對映像的掃描前後雜湊一致；`off.write.attempts=0`。

### ★ P7-067｜稽核鏈完整性驗證

**目標**：讓稽核紀錄**可被不信任的第三方獨立驗證**——驗證程序不依賴產生它的應用程式。

**接縫**：稽核鏈（階段一的寫入閘門與審計鏈）＋ 獨立的驗證路徑（命令列模式，不需啟動圖形介面）。

**方法**：逐筆重算鏈節雜湊（前節雜湊＋本節內容），比對鏈頭；驗證工具**只讀取檔案**，不引用產生端的任何程式碼路徑；輸出第一個不一致的節索引、期望值與實測值。另提供「只驗鏈頭」與「全鏈重算」兩種模式，前者供快速抽查。

**輸出鍵**：`audit.verify.result`、`audit.verify.entries`、`audit.verify.first_bad`、`audit.verify.head`、`audit.verify.mode`。

**三態行為**：檔案不存在 → `NotApplicable`；可讀但格式不明 → `ReadError` 附讀到的前 64 位元組摘要；雜湊不符 → `Present` 且 `result=不符`（**這是資料，不是例外**）；鏈為空 → `Present` 且 `entries=0`。

**誠實界線**：鏈完整性證明「紀錄自產生後未被修改」，**不證明紀錄內容為真**（產生端若寫入錯誤內容，鏈仍然是完整的）。此界線寫入輸出。

**守門**：金標（構造三種鏈：完好、單節被改、鏈頭被改）＋性質測試（任一節被改，驗證必失敗）；正對照：刻意改一節後驗證須紅燈。

**依賴**：P1-069（鏈頭）、P1-070（獨立驗證）、P1-074（回復記錄）。

**驗收**：三種構造鏈的結果全數正確；改一節即紅燈；驗證程序可在不啟動圖形介面的情形下執行。

## 六、誠實界線與明文不做

**不做**：

| 不做 | 理由 | 解除條件 |
|---|---|---|
| 任何「是否中毒／是否被入侵」的判決 | 需判決邏輯與不可複核的推論；本專案只出事實 | 無（產品立場） |
| 安裝核心驅動、hook、注入 | 與白名單最小化及「不注入其他行程」衝突 | 無 |
| 第三方掃描引擎（YARA 等）嵌入 | 要的是掃描結果的事實，不是引擎本身 | 若引擎提供可離線、可驗證且授權相容的純解碼介面 |
| 記憶體取證（傾印取得與分析框架） | 屬另一類產品，且需核心驅動 | 無 |
| 裝置抹除、憑證清除、政策強制 | 寫入且影響系統狀態 | 無 |
| 合規判決（是否通過某標準） | 合規是機構與稽核者的判定 | 由機構提供可機器判定的條目與門檻 |

**本階段沒有證明的事**：階段七證明「信任、隔離、痕跡與稽核的**狀態**」，**不證明「這台機器或這份證據是可信的」**。即使是證據包（P7-097–P7-103），它證明的也只是「自封存後未被修改」——採集當下是否正確，取決於採集時的事實與出處，而那由階段一至六負責。
