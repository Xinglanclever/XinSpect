## 一、P2-024：SMBIOS Type 19 記憶體映射（`sb.memmap.count`／`sb.memmap.total`／`sb.memmap.{i}`）

**這一項回答「韌體說實體位址怎麼映射」，不回答「有多少可用記憶體」。** 範圍裡可能有保留區
（MMIO 視窗、快閃視窗、晶片組 holes），也可能因韌體不填而少列——所以合計與
`mem.*`／Type 16／17 那幾把鍵**不得互相代言**，那句話寫在事實的說明裡。

**規格留了兩個坑，這一支都按規格如實處理、不猜：**

| 坑 | 後果 | 這一支怎麼做 |
|---|---|---|
| 32 位元欄位單位是 **KiB**、擴充欄位是 **bytes** | 弄錯差 1024 倍，而且不會有錯誤訊息 | 兩條路徑分開換算，事實裡寫明走的是哪一條（「32 位元欄位，單位 KiB」／「經 64 位元擴充欄位」） |
| `0xFFFFFFFF` 代表「改用擴充欄位」 | 把它當數值讀會生出 4 TiB 級的假範圍；反推成 4 GiB 也一樣是假的 | 旗標設了而結構長度 < 0x1F（擴充欄不存在）⇒ 那一列標 `NotSupported`、**不合計、不反推** |

**含端點**：規格對 Ending Address 明寫 inclusive，所以大小是 `end − start + 1`。
在 KiB 單位下差一個端點是 1 KiB，在位址上卻是「這段到底覆不覆蓋最後一格」——會被拿去對帳。

**真機實測（2026-10-18，本機）**：

```
sb.memmap.count｜Present｜1 段
sb.memmap.total｜Present｜32 GB＝34,359,738,368 bytes
sb.memmap.0    ｜Present｜0x100000000–0x8FFFFFFFF＝32 GB（32 位元欄位，單位 KiB）、
                          所屬記憶體陣列 0x0047、分割寬度 4
```

**這一組數字本身就是那句話的證據**：韌體宣告的映射範圍是 **32 GiB**，
而它的意思不是「這台機器有 32 GiB 可用」——分割寬度 4 代表它橫跨所屬陣列的多個分區（交錯映射），
而位址空間的映射與 OS 看到的可用容量是兩件事。**兩個數字都對，只是回答不同的問題。**

## 二、P2-094：熱管理可讀項盤點（`ec.thermal.readable`）

**這一項問「有哪些路」，不是「溫度幾度」。** 三條口徑分開講：

1. **韌體自述**：SMBIOS Type 28（溫度探針）與 Type 29（冷卻裝置）——主機板廠填的，與 OS 無關。
2. **OS 端 ACPI 熱區**：WMI `root\WMI` 的 `MSAcpi_ThermalZoneTemperature`，值以 **0.1 K** 表示。
3. **EC（嵌入式控制器）**：**本專案沒有直接讀 EC 的通路**——事實裡明寫這一條，
   因為「沒有這一項」與「這一項是 0」在畫面上長得一樣，而它們是不同的斷言。

**四種「沒讀到」被分開陳述**（這是這一項真正的內容）：

- **這條路失敗**（權限不足／查詢錯誤）；
- **這條路查成功但機器沒有這一項**（熱區 0 個＝查證後的「沒有」）；
- **查到了但值回 0**——驅動未填，**0 K 不是溫度**，所以那些筆數單獨列出、不計入最高溫；
- **本專案根本沒有那條路**（EC）。

**實測抓到一個值得記的細節**：本機的熱區查詢不是失敗，而是回
**「不受支援」（Not supported）**——那是**平台不提供**，與權限不足、與查詢出錯都不同。
第一版把三種都寫成「WMI 查詢失敗」，**實測把它糾正了**：現在「不受支援」有自己的一句話
（訊息文字是本地化的，所以「不受支援」與 "Not supported" 兩種都認）。

**真機實測（2026-10-18，本機）**：

```
ec.thermal.readable｜Present｜4 項
①韌體自述：Type 28 溫度探針 2 個、Type 29 冷卻裝置 2 個
②OS 端 ACPI 熱區：平台不支援（WMI 回「不受支援」——這台機器沒有可用的 ACPI 熱區物件，與權限不足不同）
③EC：本專案沒有直接讀 EC 的通路
```

**解不開的探針要能數出來**：Type 28 未達 0x14、Type 29 未達 0x0C 的結構不進明細，
但數量單獨列出——「韌體列了 8 個、我們解開 6 個」與「韌體只列了 6 個」是不同的話。
