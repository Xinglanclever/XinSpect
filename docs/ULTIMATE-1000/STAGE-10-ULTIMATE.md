# 極致計畫・階段十｜企業級、機隊、知識工程與研究級深水區

> **規格庫，不是開工指令**：圈了 ID 才開工；接縫不到 API 級不許開工。
> **計數紀律**：只有「新增能力」或「收口」才算一項。
> **本階段 105 項（P10-001–P10-105）**，域碼 9 個。前置：階段一至九全部。

---

## 一、階段定位

階段十是**終點，也是壓力測試**。它處理四類別處沒有的東西：

**其一，規模。**一台機器的事實與一百台機器的事實是不同的東西——後者要處理配置差異、條件差異與比較的有效性。機隊層不是新模型，而是**同一批事實的離線差分**。

**其二，知識。**把散落在程式裡的對照表（廠商、弱點、型號、撤銷清單）抽成可版本化、可宣告、可離線更新的知識包，並讓「未收錄」成為一種正式輸出。

**其三，研究級問題。**拓樸、物理、反解、不變式——這些是深度依賴正確性論證的項目，也是本計畫最可能被迫承認「前提不存在」的地方。

**其四，大膽區。**少數前瞻性、風險高、但若能成立就會改變工具性質的方向。它們被明文標記為大膽區，且**不計入交付承諾**（仍佔項數，見 Gate 第 6 條的註記）。

## 二、完美判準（Gate）

1. **機隊比較附條件**：跨機比較只在條件可比時輸出數字，否則輸出「不可比較」（P10-001、P10-008）。
2. **知識包可離線更新且無通道明示**：版本、雜湊、快照日期齊備，無更新通道者明說（P10-027、P10-031）。
3. **未收錄是正式輸出**：任何對照表未收錄的查詢回傳「未收錄」而非空白或猜測（P10-032）。
4. **形式化項附反例空間**：不變式測試必須說明它排除了哪一類錯誤，以及未排除什麼（P10-041、P10-045）。
5. **研究級項目標明證據等級**：檢索級／推測級如實標註，不以推測硬做（P10-051）。
6. **大膽區不計入承諾**：大膽區項目**不計入交付承諾**——它們的價值在探索，不在交付，且明確標示其風險（P10-100）。**這不等於「不計入項數」**：P10-101–P10-105 仍列在本階段的 105 項與總數 1,050 之內（2026-10-16 對帳註記）。
7. **生成層不影響事實層**：AI 相關項位於資料流末端，輸出標示為生成內容（P10-091、P10-095）。
8. **治理可對帳**：候選項、完成項、有效累計三者可機器對帳（P10-015）。

## 四、完整規格（九欄）

### ★ P10-001｜機隊離線差分

**目標**：讓「一百台機器」不必是「一百次掃描」，而是**一批可離線比對的事實快照**——在零上傳、零常駐的前提下完成。

**接縫**：既有的快照與時間膠囊機制（階段一）＋ 事實序列化格式（階段九的匯出）。輸入為一組快照檔，全部在本機處理。

**方法**：載入多份快照 → 依鍵對齊 → 輸出三類差分：**存在差異**（某機有、某機無）、**值差異**（同鍵不同值）、**狀態差異**（同鍵不同可用性）。每類差異附條件欄位（階段八），並在條件不可比時**標示不可比**而不輸出強弱結論。群組統計（同型號、同批次）由使用者以查詢語言定義，工具不預設分組。

**輸出鍵**：`fleet.snapshots.count`、`fleet.diff.present`、`fleet.diff.value`、`fleet.diff.state`、`fleet.comparable`、`fleet.group.{n}.summary`。

**三態行為**：快照不可讀 → `ReadError` 附檔名與原因；單一快照 → `NotApplicable`（差分需兩份以上）；鍵在部分快照缺失 → 列入 `fleet.diff.present` 而非視為 0；條件不可比 → `fleet.comparable=false` 並仍輸出原始值。

**誠實界線**：差分描述**事實的差異**，不描述「哪一台比較好」；配置不同的機器之間有差異是正常的，本項不區分「正常差異」與「異常差異」——那需要使用者給定的判定條件。

**守門**：金標（模式：解碼器）——以三份人工快照驗證三類差分各被正確分類；性質測試（差分對稱性：A 對 B 與 B 對 A 的差異集合互為反向）；正對照：把狀態差異併入值差異，測試須紅燈。

**依賴**：P1-077（鍵目錄）、P9-030（快照與時間線）、P8-001（條件）。

**驗收**：三類差分分類正確；對稱性成立；條件不可比時輸出標示；全程無任何網路活動（由 P1-052 的守門覆蓋）。

### ★ P10-091｜生成層護欄

**目標**：若提供生成式說明，確保它**不影響事實層、不偽裝成事實、且可被關閉**。

**接縫**：事實流末端（生成層只讀取已完成的事實集合）＋ 輸出標示機制 ＋ 出網許可清單（階段一）。

**方法**：生成層的輸入限於已收集的事實摘要；輸出**逐段標示為生成內容**；不得寫回事實集合、不得產生新的事實鍵、不得觸發新的硬體讀取。若生成需要外部服務，必須通過出網許可清單的既有條件（opt-in、使用者主動觸發、清單成文、語意如實），並在輸出中標明資料已離開本機。**預設不啟用**。

**輸出鍵**：`ai.enabled`、`ai.output.marked`、`ai.egress.used`、`ai.fact.writes`（應恆為 0）、`ai.input.scope`。

**三態行為**：未啟用 → `NotApplicable`（**這是預設狀態，不是錯誤**）；啟用但無可用輸入 → `Present` 且輸出說明無足夠事實；外部服務不可用 → `ReadError` 並回退為無生成內容（**不得以本機推測冒充**）。

**誠實界線**：生成內容**不是事實**，不得作為判讀依據；本項不提供「由 AI 判斷是否異常」的能力，那會把不可複核的推論引入工具。`ai.fact.writes` 恆為 0 是這一項的硬性不變式。

**守門**：掃描守門（模式：介面契約）——生成層不得引用事實寫入路徑，且不得直接呼叫硬體讀取；不變式測試斷言 `ai.fact.writes=0`；正對照：讓生成層寫入一筆事實，測試須紅燈。

**依賴**：P1-049（出網許可）、P1-002（骨架順序）。

**驗收**：預設狀態為未啟用；輸出逐段標示；`ai.fact.writes=0` 由測試保證；啟用外部服務時出網紀錄出現於 `ai.egress.used`。

## 六、誠實界線與明文不做

**不做**：

| 不做 | 理由 | 解除條件 |
|---|---|---|
| SaaS／雲端機隊管理 | 與零上傳、資料主權衝突 | 無 |
| 由生成層取代判讀 | 不可複核的推論不得進入事實鏈 | 無 |
| 追蹤使用者或收集使用統計 | 與零上傳衝突 | 無 |
| 對外標準化提案的實作承諾 | 標準需要外部共識才能改變 | 若標準被正式採納 |
| 大膽區項目的完成承諾 | 它們的價值在探索，不在交付 | 各項的解除條件由其規格決定 |

**本階段沒有證明的事**：階段十證明「規模、知識、形式化與研究級問題都有可陳述、可對帳的處理方式」，**不證明「這個工具已經無所不能」**。恰恰相反：本階段最重要的產出之一是 `res.gap`（前提不存在的項清單）與 `bold.marked`（不計入承諾的大膽區）。一份把「做不到」寫清楚的計畫，比一份把「都做得到」寫滿的計畫更接近可交付。
