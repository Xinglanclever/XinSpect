# 極致計畫・階段五｜網路、周邊與匯流排

> **規格庫，不是開工指令**：圈了 ID 才開工；接縫不到 API 級不許開工。
> **計數紀律**：只有「新增能力」或「收口」才算一項。
> **本階段 105 項（P5-001–P5-105）**，域碼 8 個。前置：階段一、階段三。

---

## 一、階段定位

前四階段處理的是機器**內部的固有事實**；階段五處理的是機器**與外界接觸的那一圈**：網路介面、無線、USB 與 Thunderbolt、音訊、PCIe／CXL 匯流排、以及「外設什麼時候插上來的」這條時間線。

這一圈有三個共同特徵，決定了它的成敗：

**其一，成員是環境決定的。**一台機器接什麼螢幕、插過幾支隨身碟、裝了哪些音訊端點，都是使用者的事實，不是規格的事實。因此本階段的輸出以逐裝置、逐端點、逐事件為單位。

**其二，這裡最常出現「看起來有、其實沒有」。**一條乙太網線插著但沒連上、一個 USB 埠標示 10 Gbps 實際跑 480 Mbps、一張顯示卡是虛擬顯示轉接器——這些落差不只是資料，而是驗機時最常被問到的問題。本階段的核心產出正是**供給與實測的落差**。

**其三，這裡是唯一「與外部世界有連線」的地方**，因此資料邊界（階段一的匿名化與出網許可）在此必須最嚴格執行：位址、SSID、MAC 一律在匯出時遮蔽。

---

## 二、完美判準（Gate）

1. **供給與實測的落差逐項陳述**：PCIe 供給速率對線路速率、USB 埠標示速度對實測速度、顯示卡的實體／軟體／基本顯示驅動三態，全部以落差形式輸出（P5-010、P5-033、P5-045）。
2. **識別資訊可遮蔽且不影響對帳**：MAC、SSID、BSSID、遠端位址在匯出時遮蔽，但遮蔽不破壞與其他事實的交叉對照（P5-005、P5-020）。
3. **外設時間線可離線重跑**：以結構化段落解析，**不解析在地化欄位**（P5-073、P5-081）。
4. **監聽面三方對照**：監聽埠與程序、服務、防火牆規則三方對照，不一致具名（P5-084）。
5. **匯流排錯誤可對照**：AER／匯流排錯誤計數與階段二的韌體表、階段三的 MCA 並列（P5-059）。
6. **音訊延遲下限可量且附條件**：緩衝區與取樣率推得的延遲下限，附量測條件（P5-046）。
7. **熱插拔事件有時間戳**：每次連接與移除可對到時間線（P5-076）。

## 四、完整規格（九欄）

### ★ P5-073｜外設連接時間線（`setupapi.dev.log`）

**目標**：把「這台機器插過哪些裝置、什麼時候第一次、什麼時候最後一次、裝了哪支驅動」變成一條可排序的時間線——完全離線、唯讀、不需任何驅動。

**接縫**：`%SystemRoot%\INF\setupapi.dev.log`（純文字日誌）＋ 裝置列舉 API 補足現況。**只解析結構化段落**（`>>> [Device Install]`、`<<< Section end`、裝置實例路徑、時間戳），**不解析在地化欄位名稱**。

**方法**：逐段落掃描 → 以裝置實例路徑（`USB\VID_xxxx&PID_xxxx\...` 等）為鍵聚合 → 記首次／末次時間、驅動名稱與版本、區段結果（成功／失敗）。無法歸類的段落計數並列出開頭片段，不猜測其語意。

**輸出鍵**：`setup.events.count`、`setup.device.{id}.first`、`setup.device.{id}.last`、`setup.device.{id}.driver`、`setup.unparsed.count`、`setup.timeline.range`。

**三態行為**：日誌檔不存在 → `NotApplicable`（**舊系統或已輪替的日誌不算錯誤**）；日誌存在但無可解析段落 → `Present` 且 `setup.unparsed.count` 等於總段落數；日誌被截斷（輪替）→ `ReadError` 附實際讀到的起始時間；時間戳格式異常 → 該段落計入未解析。

**誠實界線**：日誌描述的是**安裝事件**，不是「裝置現在還在」；本項不推論裝置是否被刻意移除，也不解析廠商自訂段落。日誌會被系統輪替，因此時間線**必有起點而未必涵蓋全程**，此限制寫入輸出（`setup.timeline.range`）。

**守門**：金標（模式：解碼器）——以三種語系（繁中／英文／簡中）的日誌切片作 golden，斷言三者得到**相同的結構化結果**（這正是「不解析在地化欄位」的可執行證明）。

**依賴**：P1-009（離線輸入接縫）、P1-023（出處）。

**驗收**：三語系切片結果一致；輪替日誌不崩潰且輸出起點；未解析段落計數與人工抽樣相符。

### ★ P5-084｜監聽埠三方對照

**目標**：回答「這台機器在等誰連入」，並把**監聽埠、佔用它的程序與服務、以及防火牆是否放行**三者並列；任一不一致都具名。

**接縫**：連線表（TCP／UDP 監聽狀態）＋ 程序與服務對照 ＋ 防火牆規則集合；三方皆為唯讀查詢。

**方法**：列舉所有監聽端點（協定／位址／埠／PID／程序名）→ 對每個埠解析其所屬服務與防火牆規則（含設定檔）→ 輸出三方對照表與落差清單。系統保留埠與已知埠以知識包標註，未收錄者顯示「未收錄」而非猜測。

**輸出鍵**：`listen.count`、`listen.{proto}.{port}`、`listen.orphan`（無對應程序的監聽）、`listen.unfirewalled`（無規則放行的監聽）、`listen.cross.diff`。

**三態行為**：需要權限而不可讀 → `InsufficientPrivilege`（**仍輸出可讀的那部分**）；連線表可讀但零筆 → `NotApplicable`；埠存在但服務無法解析 → `Present` 且列入 `listen.orphan`；防火牆不可查 → 該欄標 `Unknown` 而非空白。

**誠實界線**：監聽**不是**漏洞，本項不給風險結論；也不掃描遠端、不嘗試連線。系統埠與應用埠的區分依知識包，知識包未收錄時明說未收錄。

**守門**：掃描守門（模式：介面契約）——本項不得出現任何連線（connect）呼叫；以假來源注入三個互不一致的埠，斷言落差清單正確列出三項。

**依賴**：P1-040（埠知識包）、P6-030（服務清單）。

**驗收**：真機輸出與 `netstat -ano` 抽樣一致；三個假不一致案例全部被列出；未收款項顯示「未收錄」。

## 六、誠實界線與明文不做

**不做**：

| 不做 | 理由 | 解除條件 |
|---|---|---|
| 封包擷取與協定級捕獲 | 需安裝核心級捕獲驅動 | 若作業系統提供免驅動且唯讀的擷取介面 |
| 主動掃描、連線測試、連接埠敲擊 | 會對外部世界產生流量，且與唯讀立場衝突 | 無 |
| 協定分析儀功能（PCIe／USB 眼圖與協議解碼） | 需硬體 | 無 |
| 圖形 API 注入與逐幀擷取 | 需注入其他行程 | 無 |
| 寫入網卡設定、修改防火牆規則 | 寫入且影響系統狀態 | 無 |

**本階段沒有證明的事**：階段五證明「這台機器與外界接觸的那一圈長什麼樣、落差在哪裡」，**不證明「網路安全不安全」**。監聽埠、防火牆落差、協定旗標都是事實；把它們讀成「有風險」是使用者的判讀，本階段只負責讓那個判讀有可查的依據（P5-102 的報告明示此界線）。
