# 曦覽 XinSpect 3.13「Ultima XIII」

## 這一版做了什麼

### 一、新增「監控規劃」頁：十個設計試算

工具群組多一頁 **監控規劃**，把監控案場最常被算錯的十件事放在同一張紙上：

| 計算器 | 回答的問題 |
|---|---|
| NVR 儲存容量 | 這個碼率、頻道數與保留天數要幾 TB；RAID 之後可錄幾天、還差多少 |
| 接入頻寬 | 所有攝影機加協定開銷後，上行與 NVR 接入會不會塞 |
| PoE 功率預算 | 總瓦數、保留量、餘裕，以及每機瓦數是否超過 PD 上限 |
| 交換機背板／包轉發 | 全雙工背板與 64 bytes 最小訊框的 pps 需求 |
| 光纖衰減 | 光纜、接頭、熔接三段損失之後還剩多少裕度 |
| 攝影機端壓降 | 線長與線徑吃掉幾伏，攝影機端還剩幾伏、PSE 要不要多供瓦數 |
| 佈線用線量 | 含餘裕的總長與整箱數（無條件進位） |
| RAID 可用容量 | 各等級的資料碟數、可用 TB、效率與容錯顆數 |
| 無線覆蓋 | 頻寬與覆蓋兩個瓶頸取較大者，需要幾台 AP |
| UPS 與機櫃 | 電池 Wh 換算續航分鐘；裝置＋保留是否塞得進機櫃 |

共同原則：

- **輸入是宣告、輸出是推導。** 這一頁不讀本機硬體，每一個數字都是公式算出來的；
  畫面上寫明「不是量測值」，假設（十進位 GB／TB、接頭 0.5 dB、熔接 0.15 dB、64 bytes 訊框）
  逐條列在頁尾。
- **輸入不足就說輸入不足。** 任何一個計算器對空值都不會丟例外、也不會給一個看起來合理的假數字。
- **壓降解二次式。** 不是拿 `P ÷ V` 當電流：攝影機端電壓與電流互相牽制，線太長時二次式無解，
  畫面會直接說「這條線供不起」，而不是給一個負的或零的電壓。
- 可以按「儲存這份規劃」把輸入存成本機 JSON（不上傳）；下次啟動時同一組結果以 `plan.cctv.*` 進事實集，匯出報告會多一節「監控規劃（設計試算）」。「複製摘要」則把十段結果貼成純文字。

### 二、藍色中隊：預設關閉，並補上 Win11 基線

**預設關閉。** 守護進程（`BlueSquadronBridge.exe`）會在背景常駐輪詢、載入核心驅動，
不該替新使用者預設打開。新安裝的使用者第一次進來會看到「守護進程已關閉（唯讀態勢評估照常）」，
要即時防護的人自己到安全頁把開關打開，選擇會記進設定檔；唯讀的態勢評估不受影響。

**新增檢查**（都走登錄檔、唯讀、讀不到記「未評估」）：

- SMB 簽章與 SMB 加密
- NTLM 限制（`LmCompatibilityLevel = 5`）
- 攻擊面縮減規則（ASR）在封鎖模式的條數
- Smart App Control（強制／評估／關閉三態）
- PowerShell 指令碼區塊記錄
- Defender PUA 防護與排除路徑數量
- 自動播放／自動執行

**修掉三處「不知道被記成通過」：**

1. `BitLockerDmaProtection ?? BitLockerEnabled` 等於在 DMA 保護讀不到時替「含 DMA 保護」背書；
   現在分成「兩者都有」「只有 BitLocker（DMA 未回報，不宣稱）」「兩者都讀不到（未評估）」三種。
2. Thunderbolt 安全等級讀不到時，原本寫「未偵測到控制器（無此攻擊面）」並算通過；
   但讀不到也可能是驅動沒回報——現在記「未評估」，不進分母。
3. `IsServiceRunning` 在 WMI 失敗時回 `false`，於是「WinRM 已停止」「Print Spooler 已停止」
   自動變成兩項通過。現在失敗回 `null`，由上層記「未評估」。

### 三、M.2／U.2 分析不再拖住主視窗

`M2AnalysisService` 在 `MainViewModel` 的欄位初始化式就被建立，原本在建構子裡同步讀 SMBIOS
與兩個 WMI 命名空間——任何一個卡住，主視窗就不會出現。3.13 改成：

- 收集（`Collect`）丟到背景、套用（`Apply`）回 UI 執行緒；
- 磁碟清單走 `WmiGuard` 的 3 秒上界；
- 讀不到時分開講「WMI 無回應」與「讀取失敗」，不再留白冒充「沒有磁碟」。

## 驗證

- 全套 `dotnet test`：測試數總計見 `Tests/TestSuiteBaseline.cs`；三份 README 的徽章與它同源。
- 新增 `SurveillancePlanningTests`：每個計算器的期望值都在註解裡留算式，係數一改就紅燈。
- 新增 `SurveillancePlanningViewTests`：頁面在 STA 執行緒上載入，十段結果都要有值。
- 新增 `M2AnalysisTests`：注入假磁碟、逾時與快速失敗三條路徑。
- 藍隊：`SecurityScoreTests` 多了「新基線每一項都有自己的發現」與「Smart App Control 評估模式只算部分」。

## 已知限制

- 監控規劃是設計試算，不是量測：驗收前仍要實測（PoE 壓降、光纖插入損失、實際錄影碼率）。
- 光纖係數與接頭／熔接損失取最壞情況的工程慣例；實際值依光纜規格與施工品質。
- Smart App Control 與 ASR 多為 Windows 11 企業／教育版才有；讀不到就記未評估，不當成缺口。
- 監控規劃的數字只在「按了儲存」之後才進事實集與報告（`plan.cctv.*`）；沒存檔就不產鍵，不拿一堆 0 冒充有規劃。
