## 三、三語策略（**二階段暫緩**——2026-11-07 裁定，繁中達標後另議，以下保留為屆時藍本）

- **繁中是主稿**，唯一的事實來源；簡中與英文從繁中**翻譯層**生成，術語表以 `Services/EnglishStrings.cs`＋`README.en.md` 為基底擴充（估需 2,000+ 術語條目，含：六態名、可信度名、指令名、鍵域名的定譯——**術語表本身是一章**，約 3 萬字元）。
- 簡中轉換走「詞級轉換＋術語表覆蓋」，機械轉換只處理 80%，餘 20%（簡繁異形詞、技術慣用語）人工/代理複核。
- 英文不逐字直譯：第 0 部、各卷導讀**重寫**（英文讀者無繁中語境），技術章節直譯＋術語表釘死。
- 三語守門：每章翻譯完成後，抽 5 個數字/行號對照繁中原文——數字漂移即打回。

## 四、生產流水線（每章同一套）

1. **指派**：一個代理認領一章＋資料來源清單＋本卷驗證閘；
2. **生產**：代理逐檔讀源碼，寫章稿，附「數法」（每個數字怎麼數出來）；
3. **核實**：主審（本對話的審查者角色）抽 20% 斷言對樹複算，不過打回；
4. **入庫**：章稿併入主文檔，該章字數與驗證狀態記入本章頂部的申報行；
5. **三語**：繁中定稿 → 術語表翻譯 → 數字抽核。
