# 曦覽 XinSpect 3.04「Ultima XII」

把「讀不到、量不準、不知道什麼時候量的」都寫成事實：第三圈二十二輪收口，以及一批已在出貨的缺陷（第 309–330 輪）。

## 這一版做了什麼

這一版沒有大聲的功能。它做的是把這個工具最擅長的那件事做到底：**每一句宣稱都要說得出自己站得多穩**——不穩的時候要說清楚是哪裡不穩、憑什麼這樣說。

### 一、先把「量測本身有多可信」變成事實

- **這份報告的數字是什麼時候量的**（第 310 輪）：一份看起來同時量的報告，可能混著剛讀的感測器、五分鐘前的 SMART、上一次開機留下的東西。現在會給出最早／最晚／跨度／幾組不同量測時刻，以及逐域列出「落後最新一刻超過 5 秒」的名單。只寫事實不寫評語——落後 3 秒與落後 3 天都是事實。
- **這一頁為什麼慢**（第 311 輪）：104 個收集步驟全部包進計時器，總計幾毫秒、最慢的三步、其中幾步失敗。並明寫「逐鍵代價未量」——一個步驟可能生產數十把鍵，攤出來只會得到沒有意義的精確數字。
- **這個數字能信到哪裡**（第 313 輪）：8 個即時量測域的視窗、換算式、精度由誰決定，列成表格。其中 4 個域的精度由驅動決定，本機就明白宣告**不給誤差上限**——那比隨手寫一個 ±0.5 °C 誠實。
- **同一把鍵連量五輪**（第 312 輪）：最小／最大／平均、跨度、首末漂移、N 輪中 M 輪有值。不給穩定度分數、不比閾值、某一輪沒讀到不補值。
- **同型號族群基線**（第 328 輪）：同一型號換過三台，只有本機基線看得出這台與同型不同。全部在本機計算，只讀自己存過的快照——不是「先上傳再匿名」，是根本不連網。樣本少於 4 份只給中位數與差值、不給 z 分數（兩三個樣本的標準差是裝飾品）。

### 二、再把「讀不到」說清楚

- **裝置診斷接進事實層**（第 309 輪）：診斷頁早就算出問題碼、驅動版本、簽章狀態，但那隻活在畫面裡。現在是事實鍵，報告與 CLI 都看得到。問題碼 `null` 與 `0` 是兩件事——`0` 是「Windows 說沒問題」，`null` 是「Windows 沒說」。
- **裝置樹全圖**（第 321 輪）：讀不到的裝置在哪一層，第一次能在報告裡指出來。
- **安全開機四環併成一筆**（第 314 輪）：PK 有了、KEK 空著、db 空著而 dbx 兩千條——這三種組合的意義完全不同。核心是**「空著」與「讀不到」不能混**：讀不到時總覽轉未知並指名是哪一環不知道，值裡明寫「但不能說四環齊備」。
- **電池健康拆成三把鍵**（第 316 輪），並修掉一個編出來的數字：既有摘要從來沒查過循環次數，卻固定傳 `0` 並印成「循環 0」——那不是「沒讀到」，是每一台有電池的機器都被斷言了一次從未發生的事。
- **Credential Guard 四層狀態鏈**（第 319 輪）、**VBS 逐服務鍵**（第 320 輪）：從一句人話變成可對帳的鍵。順手修掉一個已在出貨的標籤錯誤——VBS 總開關被標成「Credential Guard」。

### 三、新的事實面（都是唯讀，沒有新增寫入通路）

BCD 開機順序與選單等待（第 315 輪，唯讀跑一次 `bcdedit /enum`，參數寫死）｜PCIe 設定空間的兩條讀取通道並排（第 325 輪）｜類別碼三層解碼（第 317 輪，progIF 只收錄沒有爭議的七格）｜NTFS 開機磁區（第 322 輪，磁碟自己寫的字與驅動的說法對帳）｜USB 根集線器埠數（第 323 輪）｜ACPI 根指標表（第 324 輪，**驗不了的部分也說清楚在哪一層**）｜WHEA 記憶體節區（第 326 輪，「哪一條 DIMM」與「韌體沒說」的差別）｜xHCI 版本與支援速度（第 327 輪，速度值位界在公開資料裡矛盾，所以**只給原始值不換算**）｜NVMe Identify 保留區掃描（第 329 輪）。

### 四、修掉一批已在出貨的缺陷

這些都屬於「不拋例外、不紅燈，只是安靜地講錯話」那一類：

- **`smart.wctemp.*` 一直在拿 SANITIZE 能力位圖當溫度門檻**（第 329 輪）。位移寫成 `0x14A`，而它落在 `sanicap` 裡；正解是 `0x10A`（`nvme.h` 與 `libnvme-types.h` 兩份標頭一致）。程式與測試用了同一個錯誤假設，所以一路綠燈。
- **USB 埠數用 16 位讀**（第 324 輪）：把 `wHubCharacteristics` 的低位元組一起吃進來，一台 8 埠的機器會顯示成兩千多埠。同一批還修了：IOCTL 傳 `null` input 讓整個功能歸零、USB 3 的 `0x2A` 描述元不採信（現代機器上每一個 xHCI 根都讀不到埠數）。
- **子行程死鎖**（第 330 輪）：同步讀排在「等逾時」之前，子行程灌爆 stderr 時會雙向死鎖，而等待那一行**永遠走不到**——那個逾時從來沒有生效過。收成一支共用執行器，逾時殺整棵行程樹。
- **原子寫入的暫存檔名**（第 330 輪）：固定的 `.tmp` 在多實例下會讓 A 把 B 的半成品搬成正式檔。
- **歷史倉的尾端垃圾**（第 330 輪）：崩潰後新的一筆會被讀在錯的位移上而丟失。
- **外部報告無上限**（第 330 輪）：選到一個 3 GB 的 HWiNFO 全紀錄就是一次大配置；現在超過 64 MiB 明白回報「檔案過大」，把界線寫進狀態字串，不靜默回一個空表。

## 這一版沒有做的事

不是謙辭，是真的沒做：

- **沒有新增任何硬體寫入通路。** 全部新增面都是唯讀；超頻、MSR 寫入的驗證範圍沒有變。
- **沒有把 xHCI 的速度值換算成 Mb/s。** 規格表把 PSIM 放在 bits 19:16、Linux 標頭取 bits 31:16，兩者不可能同時對——所以只輸出原始 PSI 值並寫明為什麼不算。等於承認「這個欄位我不知道怎麼讀」，而不是挑一個看起來合理的讀法。
- **沒有解讀 WHEA 事件包的外層包裝。** 那層沒有可驗證的來源，所以只列事件筆數、不解讀內容。
- **沒有替 ACPI 的 `0x50` 欄位宣稱它是哪一種 checksum。** 五個候選算法都對不上，就報原值。

## 如實申報

- **全套 7,679 條在本機跑綠**（11 分 37 秒，本機 Debug 組件）。
- **有一部分會讀真機硬體**（SMBIOS、SPD、NVMe、感測器），讀的是發版這台主機；換一台機器那些值會不同，這是預期的，不是壞掉。
- **外觀沒有逐頁在螢幕上看過。**「每一頁都建得起來」是跑過的（95 個畫面的建構測試），「看得對」是人類的活。
- **第三圈的 30 項至此全部結案**，但結案不等於每一項都量到了：其中幾項（例如 ACPI 根指標表的簽章驗證）在本機的兩條 usermode 路徑都不可得，這件事本身寫進事實裡，而不是假裝通過。
