## 1. 為什麼需要沙箱驗證

PMU 編程要寫 IA32_PERFEVTSELx（0x186–0x189）與 IA32_FIXED_CTR_CTRL（0x38D）——

1. 寫錯欄位可能讓計數器打斷（PMI 風暴）或干擾其他效能工具的設定；
2. 計數器若被 Windows 自己的 ETW／排程器占用，覆寫設定是**資源搶奪**；
3. 「只讀不寫」在編程場景不成立——編程本身就是寫。

## 2. 沙箱驗證步驟（未完成不出貨）

| 步驟 | 內容 | 通過條件 |
|---|---|---|
| S1 | 隔離環境（無重要資料的測試機）確認 PMU 版本與計數器可讀 | 能力探索與本機一致 |
| S2 | 寫入一次最小的固定計數器啟用（0x38D），讀回確認設定生效 | 讀回值＝寫入值 |
| S3 | 量測一個已知工作量（如固定迴圈 10⁶ 次），核對 instret 與預期誤差 <1% | 計數值可信 |
| S4 | 清除設定並重複 3 次——確認沒有殘留狀態、沒有 PMI 風暴 | 系統穩定、無 WHEA 事件 |
| S5 | 與既有效能工具（Windows Performance Analyzer／`wpr`）並行驗證互不干擾 | 兩邊數字一致 |
