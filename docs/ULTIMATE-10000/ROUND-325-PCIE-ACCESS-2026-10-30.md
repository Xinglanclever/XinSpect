# 第 325 輪（U10 第三圈 PC-0001）：PCIe 設定空間經哪個 API 讀——兩條通道並排，以及「一致」不代表什麼

> 候選項 PC-0001 的一句話理由是「同一張卡的兩個值來自兩個 API 時要看得出來」。
> 本專案實際上**同時有兩條**讀 PCI 設定空間的路，而在此之前沒有任何一把鍵說得出
> 「這台機器的哪一條通、它們看到的是不是同一台裝置」。

## 一、為什麼要做

兩條路的差別是真實的，而且是**能力上的差別**，不是實作偏好：

| 通道 | 機制 | 視野 | 前置條件 |
|---|---|---|---|
| 舊式 `0xCF8`／`0xCFC` | I/O 埠 → `IPciConfigReader` | **只有前 256 位元組**（register 欄 6 位元） | ring0 的埠存取 |
| ECAM | MCFG 基底 ＋ `IMmioReader` | 每功能 **4 KiB**（`0x000`–`0xFFF`） | MMIO 後端 |

所以「擴充能力鏈、AER、SR-IOV 為什麼只有一部分頁面看得到」這個問題，
答案不在任何一條通路裡，而在**兩條通路的差別**裡。在此之前那個差別只寫在程式註解裡，
使用者看不到。

## 二、做成什麼

三把鍵：

- `pcie.access.summary`——兩條路徑各自的可用性（含不可用的原因）、MCFG 條目數、
  ECAM 基底。**兩者分開寫**，因為它們可能一個通一個不通。
- `pcie.access.agreement`——兩條路徑讀**同一格**（bus 0 dev 0 fn 0 位移 `0x00`，
  vendor/device ID）的比對結果。
- `pcie.access.boundary`——界線宣告。

**沒有新增任何讀取後端**：舊式那條吃既有的 `IPciConfigReader`，ECAM 那條吃既有的
`IMmioReader` ＋ `AcpiTable.McfgEntries`。這一輪只多讀了**一個 DWORD**。

## 三、為什麼探針固定挑 0:0.0

不是「清單裡第一個」，是**固定的 host bridge**。理由：

- 舊式路徑視野是「任何 bus／dev／fn 的前 256 位元組」——位置本身不是限制；
- 但 `0:0.0` 是**唯一一定同時符合兩條路徑視野、且每台 x86 機器都有**的位置；
- 挑一個只在 ECAM 看得到的裝置來比，得到的「不一致」是假的（舊式根本讀不到那一格）。

## 四、這一輪最重要的一格：「一致」不代表什麼

`pcie.access.agreement` 寫「兩條路徑讀到同一個 DWORD → **一致**」時，緊接著寫：

> 一致的意義有限：它證明兩條通道通到同一台裝置，**不證明那個 ID 是對的**
> （要驗 ID 得回到匯流排拓撲與廠商資料庫，那是別把鍵的事）。

這是整輪最容易被誤讀的一句。兩條通道都走作業系統給的機制，它們一起錯是完全可能的
——例如 ACPI 的 `_PXM` 換算把裝置號對錯了，兩邊會一起錯。「兩邊一致」證明的是
**通道一致**，不是**事實正確**。

## 五、不一致時不判斷誰對

值裡並列兩個 ID，然後寫：

> 這不是「其中一個比較新」：同一個 DWORD 在兩條路徑上不該不同。
> 可能的原因是舊式路徑的裝置號編碼被 ACPI 的 `_PXM`／MCFG 換算動過、或是某條路徑抓到了錯誤的位址。
> **本版不判斷哪一個對**，只把兩個值並列。

## 六、四種「讀不到」都在同一個欄位裡分開

| 情形 | `Availability` | 寫什麼 |
|---|---|---|
| 兩條都不可用 | `Unknown` | 「兩條路徑都不可用——單邊不叫對帳」 |
| 只有舊式不可用 | `Unknown` | 「舊式 `0xCF8`／`0xCFC` 不可用」 |
| 只有 ECAM 不可用 | `Unknown` | 「ECAM／MMIO 不可用」 |
| 兩條都「可用」但只讀到一邊 | `Unknown` | 值裡並列兩側，「這不是不一致，是沒有兩邊可以比」 |

第四種值得單獨寫：**通道可用性**與**這一格可讀性**是兩件事。ECAM 對不存在的功能回全 F，
舊式也可能回全 F 或 0——那時兩邊都「可用」並不符合「都讀到」。

## 七、界線宣告（`pcie.access.boundary`）

1. 舊式只能定址 **256 位元組**：擴充能力鏈（`0x100` 起）與 AER、SR-IOV 一律看不到。
2. ECAM 每功能 **4 KiB**，涵蓋 `0x000`–`0xFFF`。
3. 本版只比**一格**（vendor/device ID），**沒有逐格全面比對**——那會在每台機器上
   把 4 KiB × N 個功能再讀一遍，屬明示觸發。
4. 本版不判斷哪一條路徑才對。
5. 兩條都可能同時不可用；那時只說「兩條都不可用」，**不說「這台機器沒有 PCIe」**。

## 八、本機實測

| 項目 | 值 |
|---|---|
| MCFG | 1 條目，ECAM 基底 `0x60000000`，segment 0，bus 0–255 |
| 舊式 `0xCF8`／`0xCFC` | 需 ring0（未載入驅動時不可用） |
| MMIO | 需後端（未載入驅動時不可用） |

也就是說，在**沒有載入深層存取**的預設狀態下，這一輪的兩把鍵都會是
「兩條路徑都不可用」——而那正是誠實的答案：**預設狀態下本版讀不到 PCI 設定空間**，
這件事以前沒有任何一把鍵說出來。

## 十、怎麼複算

```powershell
# MCFG 的 ECAM 基底
# （本輪的 summary 值裡直接有；沒有內建命令等價，需讀 ACPI 表）
```

「預設狀態下兩條路徑都不可用」這件事本身就是結論，所以它是可被推翻的：
載入深層存取之後再收一次，`pcie.access.summary` 應該變成「舊式可用・ECAM MMIO 可用」，
而 `pcie.access.agreement` 應該從 `Unknown` 變成 `Present` 並印出一個 ID。
**如果那時它仍然寫「都不可用」，那就是這一輪的程式有問題，不是機器。**
