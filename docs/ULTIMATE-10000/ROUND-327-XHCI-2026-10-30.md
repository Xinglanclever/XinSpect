# 第 327 輪（U10 第三圈 NP-0002）：xHCI 版本與支援速度——能力區畫得出來，通道不一定在

> 候選項 NP-0002 要「xHCI 版本與支援速度位」。那兩個東西都住在**控制器 MMIO**，
> 第 323 輪的界線宣告已經說過「usermode 讀不到」。這一輪把「讀得到的時候長什麼樣」的
> 解碼器補上，並把「這一台讀不讀得到、缺哪一步」變成可查的事實。

## 一、為什麼要做

第 323 輪的 `usb.hub.boundary` 寫著「控制器版本在 MMIO、usermode 讀不到——本版不猜，
也不從驅動版本反推」。那句話是對的，但它只是**宣告**：沒有任何一把鍵能回答
「那到底長什麼樣」。

這一輪分成兩半：

| 半 | 在哪 | 能不能跑 |
|---|---|---|
| **解碼器** | `XinSpect.Decoders/XhciCapability.cs` | 能——有 xHCI 規格逐欄位、有金標測試 |
| **生產端** | `Services/XhciControllerReader.cs` | 視後端而定——沒有 ring0 就只出「讀不到與為什麼」 |

## 二、位移照 xHCI 規格 1.1 §5.3

| 位移 | 欄位 | 內容 |
|---:|---|---|
| 0x00 | `CAPLENGTH` | 能力區長度，同時是作業暫存器區起點 |
| 0x02 | `HCIVERSION` | BCD：`0x0110` ＝ 1.10 |
| 0x04 | `HCSPARAMS1` | MaxSlots bits7:0／MaxIntrs bits15:8／**MaxPorts bits31:24** |
| 0x08 | `HCSPARAMS2` | IST／ERST Max／scratchpad hi-lo |
| 0x10 | `HCCPARAMS1` | AC64 bit0／CSZ bit2／**xECP bits31:16**（單位是 DWORD） |

擴充能力串列從 `XECP × 4` 起算，`byte0` 是 Capability ID、`byte1` 是 Next（DWORD 位移、
**相對主控基底**，不是相對前一項）。`0x02` 是「支援協定」。

## 三、這一輪最重要的一次停手：速度值不換算

PSI（Protocol Speed ID）條目裡有兩個欄位描述速度：PSIM（尾數）與 PSIS（十的次方）。
原本我照 xHCI 規格 1.1 的表寫成 `PSIM bits19:16`、`PSIS bits23:20`，然後算出
「480 Mb/s、12 Mb/s、4800 Mb/s」——**測試紅了**，因為照那個位界，尾數最多 15，
根本編不出 480。

回頭核對才發現公開資料**互相矛盾**：

| 出處 | PSIM 的位置 | 能不能編出 480 |
|---|---|---|
| xHCI 規格 1.1 的表 | bits 19:16（4 位元） | 不能（最大 15） |
| Linux `xhci-ext-caps.h` | bits 31:16（16 位元） | 能 |

兩者不可能同時對；而按後者，PSIM 又與 PSIS 的位界重疊。
**讀不出唯一定義就不編公式**——所以這一版只輸出：

- PSIV（速度編號，bits3:0，沒有爭議）
- PLT（協定：0＝USB 2.0、1＝USB 3.0、2＝兩者皆可）
- PFD（全雙工）
- **整個 PSI DWORD 的原值**

值裡明寫「速度值本版不換算成 Mb/s——那兩個欄位的位界在規格表與 Linux 標頭互相矛盾」。
候選項 NP-0002 的「支援速度位」在字面上被滿足了（位能列出來），但**沒有被換算成 Mb/s**，
因為換算需要一個本版查不到一致答案的定義。

## 四、怎麼找 xHCI 控制器

**不靠 PCI class code 猜**，而是看**誰是 `USB\ROOT_HUB30` 的父節點**——那是 PnP 樹自己說的。

位置編碼只認舊式 `bb:dd.f`；ACPI 的 `3&11583659&0&A0` 這種編碼**本版不認**，
回 `null` 並寫「這個匯流排的位置編碼本版不認」——不猜。

## 五、五種失敗，各說各的處置

| 情形 | 寫什麼 | 對應處置 |
|---|---|---|
| PCI 設定空間不可用 | 「缺 ring0 的埠存取」 | 裝驅動 |
| MMIO 不可用 | 「缺 ring0 的實體記憶體讀取」 | 裝驅動 |
| 位置解不出 | 「這個匯流排的位置編碼本版不認」 | 補編碼支援 |
| BAR0 標成 I/O 空間 | 「xHCI 能力區應在記憶體空間」 | 查控制器或 BAR 值 |
| BAR0 是 0 | 「控制器沒有宣告記憶體基底」 | 查韌體設定 |

**共同的界線**：`不從驅動版本反推`。驅動版本是作業系統的數字，不是硬體的——
拿它當 xHCI 版本會得到一個看起來很合理、但完全不是硬體自述的值。

## 六、兩個「埠數」是不同層

`usb.hub.ports.*` 是**根集線器實際回報**的埠數（hub descriptor）；
`usb.xhci.ctrl.*` 的 `HCSPARAMS1.MaxPorts` 是**主控自述它能管幾個**。

兩者不同不是矛盾：前者是 hub 說它有幾個，後者是控制器說它最多能管幾個。
這句話寫在 `usb.xhci.boundary` 的第 ⑤ 條。

## 八、怎麼複算

```powershell
# 這台機器有哪些 xHCI 控制器（ROOT_HUB30 的父節點）
Get-PnpDevice -PresentOnly | Where-Object { $_.InstanceId -like 'USB\ROOT_HUB30*' } |
  Select-Object InstanceId, Parent   # Parent 是 PnP 樹給的，不是本版推的
```

能力區本身要 ring0 的 PCI BAR 讀取 ＋ 實體記憶體讀取；沒有等價的內建命令。
本機在未載入深層存取的預設狀態下，三把鍵會寫「讀不到 · 缺 MMIO」——
那正是誠實的答案，而且**可被推翻**：載入後端重收一次，`usb.xhci.summary`
應該從 `Unknown` 變成 `Present` 並列出 `HCIVERSION` 與 `PSIV`。若那時仍寫「讀不到」，
那是程式有問題，不是機器。
