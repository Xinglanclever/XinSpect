# 第 318 輪（U10 第三圈補記）：把「同一份文件裡的第二個答案」清掉

> 這一輪沒有新增任何硬體通路、沒有改任何讀取路徑。它做的是一件事：
> **讓 README 裡同一批數字只剩一個答案**，並且給每一個答案接上一個會叫的守門。
>
> 前九輪（309–317）的主題是「那句話能不能被信」；這一輪問的是更難堪的一題：
> **同一份文件裡，同一個數字有兩個值的時候，讀者該信哪一個？**

## 一、起因：規模表全綠，正文是舊的

第 0 部那張「這棵樹的事實表（可複算）」有 `ReadmeStatsTests` 逐列守著，一直全綠。
但同一批數字在正文裡**另外寫了好幾份**，而那些地方沒有守門——於是「表格是真的、
正文是三十幾輪前的」可以同時成立。實際對帳結果：

| 數字 | 正文寫的 | 這棵樹的實況 | 出現位置 |
|---|---:|---:|---|
| 事實域 | 150 | **151** | 0.8、2.5、12 部 L-10、附錄 C、附錄 J #13 |
| 動態家族 | 49（2.6 標題還寫 55、內文 48） | **59** | 0.8、2.6、2.16、附錄 C、附錄 J #14 |
| 服務檔 | 618（附錄 C／J／K 寫 615） | **639** | 0.8、2.2 三處、2.16、附錄 C／J／K |
| 測試基線 | 7,040 | **7,467** | 0.8、0.10、10.1 敘述、12 部、附錄 C、附錄 J #2 |
| 說明條目 | 286（另一批寫 284） | **285** | 0.8、第 3 部、8 部、附錄 C／G／J |
| 可到達畫面 | 64 | **63** | 0.8、附錄 C、附錄 J #15 |
| 覆蓋基線 | 381 | **419** | 詞彙表、附錄 C |
| `[Fact]` 方法 | 6,140 | **6,151** | 10.1 |
| 方法數（Fact＋Theory） | 6,409 | **6,420** | 10.1 敘述句 |

**這九項裡有一項特別值得記**：說明條目寫 **286**，而實況是 **285**——不是落後，是**多報**。
落後可以解釋成「忘了更新」，多報只能解釋成「有人手算過一次、算錯了一個」。
兩者的處置一樣（接上單一來源），但後者更該被看見：**沒有守門的數字不只會變舊，也會變錯。**

## 二、附錄 H：地圖缺了 25 頁，還指著一頁已經拆掉的房子

附錄 H「服務檔地圖」是「找到負責某件事的檔案」的入口。它原本由一次性腳本寫成，
之後再也沒有人重跑。實測：

- 標題寫 **618** 個檔案，表上 **615** 列，磁碟上 **639** 個。
- **25 個檔案根本不在表上**（`BatteryHealthFactsService`、`BootOrderReader`、
  `MeasurementBudgetFactsService`、`PciClassFactsService`…全是第 309–317 輪新增的）。
- **1 列指著已刪除的檔案**（`Services/TroubleshootService.cs`）。
- 行數與類別數與任何一種可複算的數法都對不上（22 個檔案的行數不符，
  186 個檔案的類別數不符）——那些數字是抄的，不是算的。

**處置**：把附錄 H 接進 `Tools/gen-readme-domains.py`，成為它負責的第五個區段。
列集合直接來自 `Services/` 的走訪，行數與類別數當場算。數法寫進文件：

- 行數＝檔案以 `\n` 切開的段數（結尾有換行時等於 `wc -l` 加 1）。
- 類別數＝`class` 宣告數，含巢狀與 `partial` 的每一部分；`interface`／`record`／
  `struct`／`enum` 不計，註解行不計。

**已知邊界照實寫**：字串常數裡出現 `class ` 也會被算進來。這是這個數法的邊界，
不假裝它是編譯器的答案——附錄 H 現在開頭就有一句話說明這件事。

> 為什麼不選「所有型別宣告」？我試了四種數法（所有型別／行首型別／所有 class／行首 class），
> 沒有一種能重現舊表的數字。既然舊數字不是任何一種定義的產物，就不該替它找一個
> 「剛好對得上」的定義——那會把一個手抄的數字洗成一個看起來有出處的數字。

## 三、6.2 的「十一個域」是算出來的，但它停在舊的答案

第 6.2 節「最大的十一個域」收錄條件其實很清楚：**鍵數 ≥20**。第 309 輪 `os` 域長到
23 把之後，符合條件的域就是 **12** 個，而標題還寫「十一」。

修法不是把「十一」改成「十二」就結束——那下一次還會再漂。所以：

- 補寫 `6.2.10 os`（作業系統面的事件與裝置），原 `nw`／`st` 順延為 6.2.11／6.2.12。
- 標題與目錄一起改，並在段首說明**這份清單的邊界是算出來的，不是挑的**。
- 新增守門 `第六點二節的域清單要等於鍵數二十把以上的域`：從目錄重算門檻、清單、
  合計（396 把）與每一個小節的編號／域／鍵數。

## 四、這一輪抓到的真問題

1. **守門只盯著表格，正文就自由了。** 這是這一輪的核心：一份文件裡有兩個答案，
   而且**兩個都長得很確定**。修法不是「更勤勞地手改」，是把正文那幾處也接上同一個來源。
2. **附錄 H 的三個數字互相矛盾**（618／615／639），而且沒有人看得出來——
   因為它既沒有守門，也沒有一個「數法」可以被重算。**沒有數法的數字，連錯都錯得沒有形狀。**
3. **產生器重生之後立刻抓到自己的疏漏**：我在 `Services/FactCoverageReport.cs` 加了一個常數，
   附錄 H 的行數就該跟著變——`--check` 立刻回非零（758→767）。這正是把表格交給產生器的價值：
   **改程式碼就會有人提醒你文件要改。**
4. **`[Fact]` 與方法數的敘述句是兩個數字**：表格改了、下面那句話沒改，同一節裡就自相矛盾
   （守門 `敘述句裡的方法數要等於Fact加Theory` 一直在，這次是它把 6,409 抓出來的）。

## 七、這一輪**沒有**做的事（如實申報）

- **兩份譯本沒有跟著改。** `README.zh-CN.md` 的規模表寫「服務層文件 617 檔」、
  「測試方法 5,851 個 `[Fact]`」——那是它自己那一版（v2.99 時代）的數字，與本版差 22 個檔。
  它**自己寫明**「上面這張表其餘的數字沒有守門……讀者複算得到同一個數量級就算對得上」，
  所以那不是說謊，是**一份刻意只對四個數字同步的譯本**（`ReadmeStatsTests` 只釘住
  鍵數／家族數／測試案例數／前綴數四項）。要不要讓兩份譯本與正本逐數同步，是翻譯工作量
  的決定，不是守門問題——這一輪不動它，但記在這裡。
- **沒有改版號、沒有發佈。** 這一輪只動文件、產生器與測試。
- **沒有動任何讀取路徑與事實鍵目錄**（1,145 把鍵一把都沒增減）。
