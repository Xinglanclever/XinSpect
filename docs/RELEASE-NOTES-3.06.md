# 曦覽 XinSpect 3.06「Ultima XII」

部署器（`XinSpectDeploy.exe`）第一次真的畫出下載進度；健康頁「升級建議」的部位徽章改成看得出來的深灰。

## 這一版做了什麼

### 一、部署器：進度條、速度、剩餘時間

一鍵安裝器下載的是 35 MB 左右的主程式。在此之前，它只印一行「Downloading XinSpect.exe…」，然後就是長長的安靜——使用者不知道它在動、不知道還要多久、也不知道是不是卡住了。

現在每一支檔案下載時都會有一行即時更新的進度列：

```
  [1/4] [###########-------------]  46.9%    16.8/  36.2 MB    5.2 MB/s  ETA 0:04
```

- **進度條**只在伺服器給了 `Content-Length` 時才有。沒有分母就不編一個百分比，只寫已下載量（`  12.3 MB    5.2 MB/s  ETA --:--`）。
- **速度**是「取樣區間內實測到的位元組 ÷ 實測秒數」，每 400 ms 取樣一次。取樣不滿一個區間就寫 `--`——從 1 毫秒除出來的速度不是速度，是噪訊。
- **剩餘時間**是剩餘位元組除以同一個速度，向上取整；顯示 `0:00` 卻還在跑，比不顯示更糟。
- 行寬依主控台寬度算，80 欄時整行 79 字，不折行（折行的話 `\r` 只會回到最後一行的行首，每畫一次就多一行殘影）。

**順手抓到一個從第一天就在的問題。** 舊版把進度掛在 `WebClient.DownloadProgressChanged` 上，但那個事件只在非同步下載時觸發；同步的 `DownloadFile` 一次也不回呼。也就是說，那段進度顯示的程式碼從來沒有執行過。這一版改成自己讀回應、逐塊寫檔。

多一道守門：實收位元組不等於 `Content-Length` 就當斷線，刪掉半截檔並報錯。先前的 PE 檢查（開頭是不是 `MZ`、夠不夠大）擋不住截短的 exe——它兩項都符合。

### 二、升級建議：部位徽章改成深灰

「升級建議」每張卡片上有一顆部位徽章（儲存／記憶體／處理器／顯示卡／散熱／系統）。它原本用的是 `SurfaceBrush`（`#1a1a19`）——比卡片底色（`#232322`）更深、又幾乎與頁面底色同色，看起來像卡片上的一個洞，而不是一顆標籤。改成深灰（`#3a3f46`）底、淺字之後，掃視時分得出每條建議屬於哪個部位。

## 這一版沒有做的事

**磁碟種類的判定沒有改。** 種類是在 `DiskInfoService` 由 `BusType`／`MediaType`／轉速推斷的，**不依賴 SMART**；三者都沒有回報時種類落在 `Unknown`，而 `Unknown` 不算機械硬碟，所以「系統碟換成 NVMe 固態硬碟」「把常用資料從機械硬碟搬到固態硬碟」這兩條規則會整條略過。這一版只改標籤的辨識度，沒有改判定，也沒有新增任何硬體讀取通路。

## 如實申報

- 部署器的新進度列由 `Installer/tests/ProgressTest.cs` 驗證：它載入**編譯後的那支 exe**（不是原始碼），用反射餵它假的位元組數，再起一個本機 HTTP 伺服器真的下載三遍——完整下載、只回一半就斷線、不給 `Content-Length`。`Tools\build-installer.ps1` 每次建置都會跑它，沒全過就不產出 exe。
- 那個驗證程式需要開 `HttpListener`，**要以系統管理員身分執行建置腳本**。
- 進度列在真實網路上的外觀沒有人錄影驗證過；驗證的是「每一個數字都有出處」與「量不到就不寫」。
