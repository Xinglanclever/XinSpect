## 這一版做了什麼

官網在此之前只存在於使用者的瀏覽器書籤裡——**程式裡沒有任何一處指得到它**。這一版把它接到三個會被人看到的地方，而且是三個不同的人：已經裝了程式的人（關於頁）、正在用內建瀏覽器的人（起始頁）、在 GitHub 上讀文件的人（三份 README）。

### 一、關於頁：版號正下方一顆主色按鈕

- 用主色按鈕（與「重新讀取」「送出」同一套強調色漸層），地球圖示＋「官方網站 ↗」。
- **按鈕右邊直接寫出將要前往的位址。** 按鈕本身不透露要去哪裡，而「按下去會離開程式」這件事應該在按之前就看得到。
- 位址收成 `AppInfo.OfficialSiteUrl` 一個常數，XAML 不寫死——寫死之後改常數不會生效，而且沒有守門會發現。
- 開啟失敗走 `Diag.Swallow`，記一筆而不是靜靜吞掉。

### 二、內建瀏覽器起始頁：第一格

起始頁原本是「一排第三方工具連結」，第一眼看到的是 CPU-Z、GPU-Z、HWiNFO。現在第一格是官網卡片，整格用強調色描邊：

> **曦覽官方網站** — 產品總覽・事實目錄・三源對帳・下載與需求 ↗

理由是這個頁面的目的：先把「這個程式自己是什麼」講清楚，再談外面的工具。位置有守門——必須在格線內、且在「硬體檢測」之前。

### 三、三份 README 最上面

正體、簡中、英文各加一段引用區塊：標題級連結、一句「一頁看完」，以及一句**「網站只呈現說明，不會掃描你的電腦」**。

最後那句不是客套：本程式的定位是「唯讀、不上傳」，而「官方網站」四個字本身會讓人以為要安裝什麼或授權掃描。這句是「網站」與「程式」的分界。守門釘住「前 10 行內」——塞在第 300 行等於沒有。

### 四、說明目錄

`about/關於` 的圓圈問號補上那顆按鈕的位置與行為：只開網頁、不上傳任何資料、按之前就看得到位址。

## 六條守門

都在 `Tests/OfficialSiteTests.cs`，讀檔案內容而不是驗行為：

1. 位址是 `https`、**無結尾斜線**（否則字串比對會出現兩種形狀）、無查詢參數／片段／帳密。
2. 顯示形狀（去掉協定）與位址同步。
3. 關於頁的按鈕指向 `AppInfo`，且 XAML 內**不得出現完整位址**。
4. 起始頁的官網卡片要在 `.grid` 內，且在「硬體檢測」之前。
5. 三份 README 的連結都在**前 10 行**。
6. 三份 README 都寫了「不會掃描你的電腦」。

## 這一版沒有做的事

- **沒有新增任何硬體通路**：事實鍵 1,166 不動、服務檔 655 不動。
- **沒有把官網做成程式的啟動頁**：那會讓一個本機工具在開啟時先連網，與「零網路呼叫」的聲明衝突。按鈕是使用者主動觸發的。
- **沒有改官網本身**：站上的版本徽章現在仍是 3.03，而這一版是 3.05。這件事如實寫在這裡——**程式的版號與網站的版號目前不同步**，因為網站不在這個倉庫裡（本機找不到它的原始碼），我只能改到程式與文件這一側。要同步需要能存取那個 Worker 專案。

## 如實申報

- **全套 7,685 條在本機跑綠**（10 分 46 秒）。
- **測的是「四處寫的是同一個 https 位址」，不是「按下去瀏覽器一定開得起來」。** 後者沒有人測過——它取決於使用者的預設瀏覽器、系統關聯與權限，不是這個程式能保證的事。
- **外觀沒有在螢幕上看過**：按鈕的實際大小、圖示比例、與旁邊位址文字的對齊，都只有 XAML 層面的把握。建構測試證明它建得起來，不證明它好看。
