# XinSpect 完整體計畫 — PROGRAM (2026-09-29)

未納版控、可隨時刪。這是把五輪策略願景鎖成的「plan of record」：任何新 session 讀完就知道**做什麼、什麼順序、為什麼、本機能不能驗**。戰術層 2.0.5 收尾見 `HANDOFF-2026-09-29.md`；更大願景見記憶 `xinspect-strongest-roadmap.md`。

## 核心論點：先建三底座，功能成本才塌
五輪願景裡真正稀缺的不是功能，是三個反覆出現的底座。建好它們，HEDT/工程師/工作站/方法學整份清單的實作成本大幅下降：
1. **簽章驅動的 #GP 安全 per-core RDMSR** — #1 mesh 頻率 / #3 AVX-512 / #9 MSR 探險家共用。任意 RDMSR 必須驅動內 SEH 包住（壞索引會 bugcheck）、指定核心、WRMSR 任意寫死禁開。
2. **受控實驗＋環境把關夾具**（方法學 #5 的泛化） — 釘核心親和性＋鎖風扇轉速＋鎖頻率＋跑分內節流偵測（PERF_LIMIT_REASONS）。#1/#2/#5/#7/#12 全插在上面。料件已在：StressTestService/SensorService/CeilingService/PowerPolicyDecoder/BenchErrorMargin。
3. **SQLite bench_runs ＋ events 雜湊鏈** — 見 HANDOFF/記憶的 SQLite 地基。跨場 A/B、VBS 兩開機對照、驗機防偽都站在這。

## 已砍
- **外掛架構（IPluginPage）** — .NET in-process 外掛無真沙箱，對持有簽章 ring0 驅動的工具是不可接受的信任邊界；若復活必須出行程降權。使用者 2026-09-29 拍板砍掉。

## 本機（X299 i9-7980XE 單路 / TITAN Xp 單卡）驗證邊界
- 本機可驗：#1 #2 #3 #8 #9 #10 #11 #12、方法學全部、藍色中隊全部。
- #7 NUMA：需 BIOS 開 Sub-NUMA Clustering（單路可切 2 域）。
- #4 BMC/Redfish：需真 BMC — X299 多半沒有，別預設。
- #6 磁碟穩態：需空碟/專用碟。
- #13 GPU P2P：需 ≥2 卡，本機驗不了。
- PLP：無標準 identify 位，只能資料庫啟發式。
測不到一律誠實隱藏或標「本機未驗證」。
