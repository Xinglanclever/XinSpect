# 曦覽 XinSpect

> 一款專為 Windows 打造的原生硬體資訊總覽工具 — 即時感測、效能評測、超頻控制與一鍵裝機，全部整合於單一桌面應用程式。

繁體中文原生介面。以 WPF（.NET 10）撰寫,採 MVVM 架構,整合 LibreHardwareMonitor 感測、WebView2 內建瀏覽器,並以獨立 net48 橋接程式承載 Intel XTU SDK 進行 CPU 超頻。

## 主要功能

- **硬體總覽** — CPU / 主機板 / 記憶體 / 顯示卡 / 儲存裝置的完整規格,含主機板廠商徽章與 CPU 官方 logo。
- **瓶頸診斷** — 把散在各頁的讀值合起來看一次,回答「現在是什麼在拖住這台機器」:溫度牆、功耗牆、單執行緒、記憶體、儲存、顯示卡、驅動 DPC、電源政策、MCA 平台事件,依「該先看哪一條」排序。每一條都附上產生它的數字與該去哪一頁量得更清楚;**沒量到的資料不會被當成沒問題**,而是列進「還沒納入判斷的部分」。全程唯讀,不會自動發動任何會讓機器發熱的量測。
- **記憶體插槽配置圖** — 主機板上每個插槽的實體排列,實心=有模組(容量／速率)、虛線=空槽。通道字母由韌體的插槽命名推斷;只寫 `DIMM0／DIMM1` 的板子就直說看不出通道,不硬湊 A/B——猜錯通道會害人把記憶體插到錯的槽。
- **即時感測** — 溫度、時脈、電壓、風扇、負載即時儀表,支援迷你懸浮視窗與系統匣。
- **溫度負載警示** — 可設定門檻,超標時橫幅提示 + 系統匣氣泡通知。
- **感測記錄** — 一鍵匯出 CSV,長期追蹤。
- **效能評測** — 內建多項基準測試,並可自我驗證:棋類跑分(中國象棋／西洋棋)以 perft 葉節點數當檢核碼,那是數學常數,算出別的數字就是這台機器算錯了,而不是比較慢。
- **效能天梯** — 離線 CPU / 顯示卡天梯榜(資料來源 topcpu.net),快速定位自己的硬體排名。
- **CPU 超頻** — 透過內建 Intel XTU 橋接程式調整倍頻 / 電壓；倍頻與電壓併在同一張「目標時脈規劃」卡（含類比電壓錶與微調鈕），因為拉多少頻率、給多少電壓本來就是同一個決定。
- **顯卡超頻** — NVML 功耗 / 風扇 / 溫度監控 + NVAPI 時脈調整。
- **系統風扇控制** — 主機板 / Super I/O 上可控風扇的手動調速與一鍵還原自動（與感測共用同一套 LibreHardwareMonitor 引擎，真實寫入硬體）。
- **硬體檢測** — 「實用工具 → 硬體檢測」內建全螢幕螢幕壞點檢測、滑鼠按鍵 / 滾輪 / 回報率檢測、鍵盤逐鍵 / 防鬼鍵（NKRO）檢測、喇叭聲道與掃頻、動態拖影與幀間隔，純原生輸入事件、零外部相依。
- **一鍵裝機** — 整合 winget,勾選常用軟體批次安裝。
- **工具箱** — Windows 內建工具一鍵開啟＋八十餘款第三方硬體工具的**官方**下載捷徑（本程式不內含任何外部執行檔）。會寫韌體、整碟抹除或改開機結構的項目掛「危險」／「注意」徽章並寫明最壞情況——標了等級就必須說出後果，不准用「請小心使用」帶過（有測試守住）。沒有官方發佈站的工具（USB 主控量產工具那一類）刻意不收，不為了把清單堆長而指向來源不明的連結。
- **內建瀏覽器與終端機** — WebView2 內嵌瀏覽,以及真實 `cmd.exe` 終端機。
- **AI 評價** — 接 Ollama 或任意 OpenAI 相容端點,對本機硬體給出評語(提示詞可自訂)。
- **效能天花板** — 回答「這顆 CPU 為什麼跑不到它該有的頻率」：節流溫度 TCC、PL1／PL2 與時間窗、電流與供電警報、Turbo 倍頻表全部直接讀自 MSR（不是規格書數字），加上自開機以來撞過的牆（限制原因暫存器的黏滯紀錄位），再由使用者親自按下的逐窗撞牆量測（基線／整數／AVX2／AVX-512）以 APERF／MPERF 量出有效倍頻與作用中核心數，最後歸因成一句判決：溫度牆、功耗牆、電流牆、供電模組過熱、自主 P-state、多核渦輪上限，或「缺口不在硬體」。全程唯讀，**不寫入也不清除任何黏滯位**；能量計未通過自我驗證就只給原始計數、不換算成瓦。
- **硬核唯讀量測** — 直接編程 Intel PMU／MSR 的底層事實：Top-down 管線歸因、頻率真相（MPERF／APERF 與 Turbo 階梯）、平台可信度、BIOS 與 ME 微碼、逐核時間歸因、電源政策、記憶體真實面貌、機器檢查（MCA／WHEA）、核心間延遲矩陣、RDT 快取佔用。全部唯讀，取樣前後完整還原計數器；**量不到的項目一律拒絕出數字**而不是猜一個看起來合理的值。
- **隱形停頓** — 系統管理中斷（SMI）的次數與封裝／核心的 C-state 駐留。SMI 由韌體在作業系統看不見的模式裡處理，工作管理員永遠 0% 但音訊會爆；硬體只留下次數、沒有留下每次待了多久，所以**只給頻率，不乘一個猜出來的耗時**。
- **NVMe 電源狀態** — 碟宣告的電源狀態表（各階功耗、進入與離開延遲）對實測的「刻意閒置 N 毫秒後第一筆 4K 讀取要多久」。閒置後的第一筆為什麼慢，這裡回答得出來；兩者同一量級才敢歸因於省電狀態。
- **Resizable BAR 實況** — 顯示卡的記憶體視窗被撐開了沒有。ReBAR 要 BIOS 開、驅動支援、CSM 關掉、純 UEFI 開機、開機碟是 GPT，缺一個就不生效，而 Windows 沒有任何地方告訴你現況。刻意不走 PCI 設定空間（ReBAR 的能力結構在 0x100 之後，傳統的 CF8/CFC 機制到不了），改問 Windows 實際指派給裝置的記憶體範圍——那是真的生效的視窗，不是能力宣稱值，也不需要驅動或管理員權限。覆蓋率只當事實列出不拿去打分數：BAR 尺寸是 2 的次方，12 GB 的卡最大只拿得到 8 GB 視窗，那是規格使然。
- **顯示鏈路真相** — 解析度與刷新率開起來了，不代表畫面沒被犧牲：頻寬不夠時驅動會自己把色度降成 YCbCr 4:2:2 或 4:2:0，設定裡照樣寫著 4K144。列出連接技術、實際像素時鐘、色彩編碼、位元深度與 HDR 狀態，並算出這個模式需要多少影像資料率。
- **大頁與位址轉換成本** — 同一份亂序指標鏈、同樣大小的工作集，在 4 KB 頁與 2 MB 大頁上各跑一次；唯一的變數是頁面大小，兩者的差就是分頁表走表的代價。「配不出大頁」與「大頁沒有效益」分開講。
- **L3 未命中與 DRAM 實際流量** — 用架構效能事件數出真的去了記憶體幾次，並先拿一段**已知大小**的負載自我驗證；對不上就只給原始計數、不換算成頻寬。
- **執行緒遷移與排程落點** — 執行緒在核心之間彈跳得多兇，以及每一跳丟掉哪一層快取。ETW 的核心上下文切換事件（零驅動、需管理員），把每條執行緒上次落在哪顆核記下來，換了就是一次遷移，再依拓樸分成四層：同實體核心（SMT 兄弟，L1/L2 都還在）、同末級快取內換核、跨末級快取（連 L3 都要重新拉）、跨 NUMA（記憶體變遠端）。邊收邊累加不留原始事件，並**扣掉自己**——量測本身也是一條在跑的執行緒。行程排名依遷移率而不是絕對次數，後者只會把最忙的排前面。刻意不下判決：遷移多寡取決於工作型態，不是缺陷。
- **NVMe 錯誤日誌與關鍵警告** — 「這顆碟開始要壞了」最早的證據在 NVMe 的錯誤資訊紀錄（log page 0x01）裡：每一筆記著出錯的命令、狀態碼與 LBA，而 Windows 完全不看它。連同健康紀錄（0x02）的關鍵警告逐位元解讀——備用空間見底、已進入唯讀模式、揮發性快取備電失效，每一位元都是一句可行動的話，不再只給一個「0x0002」。空槽位不列（一排「#0」會被讀成碟上有 64 筆錯誤），查不到的狀態碼照實回報原始 SCT／SC。
- **中斷落在哪顆核** — DPC／ISR 排行說得出哪支驅動跑太久，這裡說得出它的中斷落在哪顆核上。「明明還有很多核閒著卻很卡」的一種成因。
- **睡眠與喚醒** — 半夜自己醒來看喚醒來源與喚醒計時器，睡不下去看電源請求。刻意不解析 powercfg 的輸出文字（那些字隨系統語言翻譯，比對關鍵字會靜靜失效）。
- **網卡進階屬性** — RSS 接收佇列與驅動開放的每一項設定。RSS「開著」不等於「有效」：只有一條接收佇列時所有收包處理仍落在同一顆核上。
- **開機耗時分解** — Windows 早就把「哪一支服務、驅動或啟動項比平常慢」寫在事件記錄裡了。排序依比平常多花的時間而不是總時間。
- **體質評分（矽晶品質特徵化）** — 不是單點猜測：程式自己控制負載階梯（1／2／4… 顆實體核心滿載），而同時活躍的核心數本身就是睿頻表的索引，處理器因此會自己沿原廠 V/F 曲線移動——**全程唯讀，不寫任何倍頻或電壓**。逐階取該階最低電壓與 APERF／MPERF 有效頻率湊成工作點，最小平方擬合 `V = a + k·f`，在**重心頻率**（OLS 迴歸線必過此點、預測誤差在此最小）上與世代參考線相減得 ΔV，再以族內離散 σ 換成推估百分位並附 95% 區間。階梯順序刻意由兩端往中間交錯，否則溫度隨核心數單調上升而頻率單調下降，兩者完全相關，就分不出斜率裡有多少是漏電貢獻的。型號不在參考表內、工作點少於三個、頻率跨距太小、或**你已手動改過核心電壓**（那時量到的是設定值不是矽晶的要求）——任一成立就只給實測值、不給百分位。
- **簡易模式與首次啟動選擇** — 側邊欄只列一般使用者用得到的頁面（約 20 頁），直讀暫存器那一類的進階頁先收起來。只是不顯示，不是停用：`Ctrl+K` 照樣搜得到每一頁。第一次啟動會問一次要「簡略」還是「詳細進階」，並直接寫明之後去哪裡換。
- **同時開多份** — 預設允許（設定 › 一般可關回單一實例）。並排比對兩份報告、或一邊燒機一邊在另一個視窗翻別的頁面時用得到；設定與歷史是「最後寫入者贏」、WinRing0 驅動全機共用這兩個實際後果都寫在說明裡而不是藏著。
- **複製規格摘要** — 總覽頁一鍵把八行規格複製到剪貼簿，貼到論壇或聊天室問人。不含電腦名稱、使用者名稱與任何序號。
- **Windows 授權** — 是不是正版、重裝之後會不會掉、能不能移到新電腦。韌體內嵌金鑰預設遮蔽，按了才顯示，且只顯示在畫面上。
- **這台機器多老了** — 由 Windows 安裝日期、韌體建置日期與磁碟通電時數推估，三個線索的偏誤方向都寫在卡片上。沒有出廠日這種暫存器，所以說的是推估，不是事實。
- **深淺主題與八色強調色** — 執行期即時切換，已經在畫面上的元素同步換色；落在強調色上的文字色依對比度自動挑選，八個強調色都達到 WCAG AA 的 4.5:1。
- **診斷紀錄** — 所有「已接住、功能降級」的例外（MSR 被拒、WMI 失敗、感測器不存在）連同對使用者的實際後果，都列在設定頁並落地 `diag.log`；「量不到」與「程式有缺陷」不再長得一模一樣。
- **歷史回放與報告匯出** — 分鐘級極值長期落地,可回放任意時間窗;整機報告可匯出 HTML／Markdown／純文字(可選遮蔽可識別資訊)。
- **命令面板** — `Ctrl+K` 模糊搜尋直達 25 個分頁與 23 項實用工具（簡易模式收起來的頁面照樣搜得到）。
- **集中設定** — 所有偏好以 JSON 持久化,支援一鍵初始化。
- **動態視覺效果(可關)** — 逐核液柱的液面／波紋／氣泡、風扇葉片轉速、七段數字面板,每一個「動」都對應一個真實讀值,沒有純裝飾的動畫。因為重繪要花 GPU 與封裝功耗,而那會進到量測結果裡,所以設有全站總開關;跑分與撞牆量測期間程式也會自行暫停動畫,且不會動到你的偏好設定。

## 系統需求

- Windows 10 / 11 或 Windows Server(x64)
- 部分功能(超頻、感測)需以**系統管理員**身分執行
- 顯卡超頻功能需 NVIDIA 顯示卡與對應驅動

## 建置

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download)。

```bash
git clone https://github.com/Xinglanclever/XinSpect.git
cd XinSpect
dotnet build -c Release
```

執行:

```bash
dotnet run -c Release
```

發佈單一執行檔:

```bash
dotnet publish -c Release -r win-x64
```

> 建置時會自動以巢狀 MSBuild 編譯 `Bridge/`(net48 的 Intel XTU 橋接程式)並內嵌為資源,毋須手動處理。
